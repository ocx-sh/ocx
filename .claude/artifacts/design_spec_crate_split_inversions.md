## A. Rulings on the open conflicts

### A.1 The `log.rs` shim — dissolves (D-001..D-003)

**Evidence.** `log.rs:4` is `pub use tracing_log::log::*;`. 86 files / 164 `use crate::log` sites in `ocx_lib/src`; 25 more in `ocx_cli/src`. 487 `log::{debug,info,warn,error,trace}!` sites vs 72 `tracing::*!` sites already in the tree. Of the **83** disallowed refs into `ocx_console` (the orchestrator's "72"), **81 are `log`/`log::*`** and the other **2 are `cli::progress::LOG_INTERVAL`** (`archive/tar.rs:13`, `archive/zip.rs:15`; defined `cli/progress.rs:7`, no other user). Per crate: announce 2/2, config 11/11, index 14/14, package 8/8, project 17/17, setup 5/5, sign 2/2, store 12/12, trust 1/1, util 9/11. No `log::log!`, no `target:`, no `log_enabled!` anywhere; the only non-macro use of the facade is one test logger (`oci/index/local_index.rs:1512–1537`, `CapturingLogger` via `set_boxed_logger`). The CLI subscriber (`cli/log_settings.rs:80–83`, `:125–128`) uses `registry().with(fmt_layer).try_init()`, which installs `tracing_log::LogTracer` (tracing-subscriber default feature `tracing-log`) — that is how `log::` records reach the subscriber today.

**Ruling (as amended by plan DEC-1).** `log.rs` is deleted; every library site calls the `log` crate's macros directly (`log::<level>!`; `log` becomes a workspace dependency) — not `tracing::<level>!`: 487 `log::` sites versus 72 `tracing::` sites make this a one-token `use` edit per file rather than a macro rewrite. Both families render identically under this subscriber (`.compact()`, `with_target(false)`; `LogTracer` dispatches with `Parent::Current` and the tree enters no span), so the choice is diff size, not behaviour. `log = { version = "0.4", features = ["std"] }` — `std` because `local_index.rs:1533` calls `log::set_boxed_logger`. `tracing-log` leaves every library manifest; `ocx_cli` keeps it (the `LogTracer` bridge lives with the subscriber). `LOG_INTERVAL` moves to `ocx_util::archive` (its only users). The `CapturingLogger` test (`local_index.rs:1512–1537`) is kept as is — only its `use` line changes. This removes 81 of 83 `→ ocx_console` refs and the "8 crates name `ocx_exit` alone" claim in ADR § Rulings OQ3 becomes true by construction.

**Mechanism.** One sed over 86 + 25 files: drop `log` from `use crate::{…}` groups (the bare `log::X!(` call sites then resolve to the `log` crate unchanged). Format strings untouched. Boundary: `no_log_facade_in_libraries` — the harness scans `crates/ocx_lib/src` for `crate::log` / `log::` macro paths with a committed negative fixture; after extraction the manifest (`tracing-log` absent) is the gate.

**Behaviour note.** Subscriber output is unchanged: `with_target(false)` at `cli/log_settings.rs:81,120`, level mapping identical, and LogTracer normalised these records into the same `EnvFilter`. The one observable delta is the *target name* (`ocx_lib::oci::client` → `ocx_oci::client`) which only a user-supplied directive can see — ruled under A.5(i).

### A.2 U1 — `env.rs`'s package-aware half (D-004..D-008)

**Evidence read.** `env.rs:1035` `set_forwarded_env`, `:1058–1088` `apply_entries` (writes the private field `package_path` at `:1070`), `:1020` `apply_child_env`, `:581–588` `ChildEnv`, `:1628` `ListSeparatorError`, `:1695` `reconcile_list_separators`, `:2280` `ForwardedEnvError`, `:2390` `encode_forwarded_env`, `:2460` `forwarded_env`, `:2568` `records` (returns `record::RecordsOptions`). Reaches: `package::metadata::env::{entry::Entry, modifier::ModifierKind, list::{DEFAULT_SEPARATOR,is_separator_edged}}` and nothing above `ocx_package` except `records()`. Callers: `activation.rs:797` (`reconcile_list_separators`, inside `project_entries`, which is itself `ocx_package_manager` code — see A.4 row 1.16), `shell/reconcile/plan.rs:503,885` (`Env::apply_entries`; `plan.rs:25–27` already imports `Entry`, `DEFAULT_SEPARATOR`, `ModifierKind` from `package`), and 8 `ocx_cli` files (`command/{exec,toolchain_exec,toolchain_env,patch_test,direnv_export,env}.rs`, `ChildEnv` at `toolchain_exec.rs:391`, `patch_test.rs:226`, `exec.rs:177`). Also `Env::inherited()` (`env.rs:749`) calls `revert_reconciled` (`:779–800`) which reaches `shell::reconcile::{CARRIER_KEY, Ledger, plan}` — source of `ocx_config → ocx_shell` (10); its only callers are 5 `ocx_cli` files.

**Ruling: map-correction — the package-aware half homes in `ocx_package`, not `ocx_package_manager`.** Both production callers may depend on `ocx_package` (map rows `ocx_shell`, `ocx_project`); `ocx_package` already owns `Entry`/`ModifierKind`; nothing in the moved items reaches above `ocx_package`. Candidate B (keep in `ocx_config`) is rejected because it closes `ocx_config ↔ ocx_package`. Inverting the two callers (candidate c) would move a pure fold out of the planner that is contracted to equal the emitted arms (`plan.rs:495–503` comment) — more code, same result.

**Mechanism.** New `package/metadata/env/apply.rs` with `pub trait EnvEntriesExt { fn apply_entries(&mut self, &[Entry]); fn apply_child_env(&mut self, ChildEnv<'_>, &OcxConfigView); }` implemented once for `env::Env` (the codebase's extension-trait pattern, `arch-principles.md` § Design Principles), plus free items `ChildEnv`, `reconcile_list_separators`, `ListSeparatorError`, `forwarded_env`, `ForwardedEnvError`, `encode_forwarded_env`, `set_forwarded_env` (private helper). `Env` gains one `pub fn note_package_path(&mut self, dir: &OsStr)` (the `:1070` write) so the trait needs no private access. `records()` becomes `record::RecordsOptions::from_env()` in `ocx_package_manager` (after A.4's `RecordsOptions` type move it is `ocx_config::records::RecordsOptions::from_env()` — same body). `Env::inherited` + `revert_reconciled` become `ocx_shell::reconcile::inherited_env() -> Env` (5 CLI call sites re-spelled). Item list that leaves `env.rs`: lines 581–588, 1035–1039, 1058–1088, 1628–1660, 1695–1798, 2280–2367, 2390–2459 (minus the two classify impls, which go to `ocx_cli` under 1.1), 2460–2579, and 749–845 (`inherited`/`revert_reconciled`); tests from 2676–6568 travel with their subject (the trampoline/launcher tests at 5975–6140 go to `ocx_package_manager::launcher`, see 1.13).

Boundary test: `env_settings_does_not_import_package` (ADR 1.10) over the residual `env.rs` + `utility/env.rs`; witness = a committed negative fixture; negative control today = `env.rs` itself.

### A.3 U2 — `ProgressManager::writer()` / `LogWriter` (D-009..D-010)

**Evidence.** `cli/progress.rs:195` `writer() -> LogWriter`; `:347–391` `LogWriter`, `LogWriterHandle`, `impl MakeWriter for LogWriter` (6 lines), `impl io::Write`, `impl Drop`. Sole consumer: `cli/log_settings.rs:121` (`with_writer(progress.writer())`, moving to `ocx_cli` under 1.3).

**Ruling.** `LogWriter`/`LogWriterHandle` with `io::Write` + `Drop` **stay in `ocx_console`** — they are the bar-suspending stderr writer, a console concern; `writer()` stays. Only the `MakeWriter` impl moves: `ocx_cli::tracing_init::ProgressLogWriter(ocx_console::progress::LogWriter)` newtype implements `tracing_subscriber::fmt::MakeWriter` by calling a new `pub fn LogWriter::handle(&self) -> LogWriterHandle` (the current `make_writer` body). **`ocx_console` does not depend on `tracing-subscriber`**; the manifest is the gate (`console_configures_no_subscriber` before extraction, `Cargo.toml` after). Behaviour: same handle, same suspend/flush path, 8 lines in `ocx_cli`.

## C. E1 dissolution design

**Shape per crate (D-040..D-046).** No crate mints a new umbrella where a module-local type already covers its failures. 88 `pub enum/struct *Error` types exist today (`.tmp/hex/plan-crate-split/` scan; per target crate: config 14, package 16, util 10, oci 9, project 9, sign 7, pm 6, announce 3, store 3, shell 2, setup 2, cli 2, index 1, script 1, trust 1). Rules:
1. A function returns the narrowest **existing** type that covers every `?` in its body. If none does, it returns its crate's root `error::Error` — which exists only in crates that already have one (`config`, `package`, `package_manager`, `project`, `index`, `store`, `shell`, `ci`, `setup`, `archive`, `compression`) — extended with a `#[error(transparent)] X(#[from] other::Error)` arm, never with a message-bearing variant.
2. The wide `Error`'s **own** variants re-home to the crate that constructs them, string-for-string: `InternalFile(PathBuf, io::Error)` (98 sites, always via `file_error`) → `ocx_util::fs::FileError { path, cause }` with `#[error("internal file error for '{path}': {cause}")]` and **no `#[source]`** (today's `.1` is not a source — `error.rs:41`; adding one would lengthen `{:#}` chains); `file_error`/`render_chain`/`append_chain` → `ocx_util::error`; `OfflineMode` → `ocx_oci::client::error::OfflineMode` (unit struct, same text; 7 constructing modules wrap it transparently); `ocx_util::error::SerializationError` takes `SerializationFailure` (`"JSON serialization error"`, `#[source] serde_json::Error`) — it is constructed in `utility/fs/locked_file.rs:402` and `utility/serde_ext.rs:28,36`, not in `package_manager` (plan DEC-11 correction); `PolicyBlocked`, `LayerLayout`, `UnsupportedMediaType`, `MetadataBlobTooLarge`, `Singleflight`, `LauncherUnsafeCharacter`, `ToolchainHomeNotAbsolute`, `LauncherPathNotUtf8` → `ocx_package_manager::error::Error` (all constructed in `package_manager` except one `UnsupportedMediaType` at `media_type.rs` → `ocx_oci::media_type::UnsupportedMediaType`, same text); `InternalPathInvalid` → `ocx_store::file_structure::error::Error`; `SymlinkWalk` → callers use `SymlinkWalkError` directly (`error.rs:64` is transparent).
3. `#[from]` boundaries point **downward only**: a crate's error may `#[from]` a lower crate's error; never the reverse. `From<Lower> for Local` is orphan-legal (research § 3).
4. **`ArcError` (4 sites)**: `oci/index/error.rs:31,81–82,112,137,535`, `oci/index/chained_index.rs:740`, `cli/classify.rs:551` (test) — all `ocx_index`. Replacement: `ocx_index::error::SharedError(Arc<ocx_index::Error>)` with the same `Display`/`source()`/`as_error` delegation (`error.rs:335–360` verbatim); `SourceWalkFailed(#[source] SharedError)`, `SourceFetchFailed(SharedError)`. The classify impl in `ocx_cli` downcasts `SharedError` and recurses via `as_error()` exactly as today (`oci/index/error.rs:393`).
5. `PackageErrorKind::Internal(#[from] crate::Error)` (`package_manager/error.rs:307`) becomes `Internal(Box<dyn std::error::Error + Send + Sync + 'static>)` with `#[error(transparent)]`: Display unchanged, the downcast ladder still walks it, and `From<ClientError>` (`:311–314`) boxes. This is the one place the wide type was a *value*, not a wrapper.
6. `pub type Result<T>` per crate only where a root `Error` exists; `prelude` dissolves to its four `ocx_util` traits.

**Order (D-047).** The wide `Error` dissolves **crate-by-crate during phase 2, inside each extraction series**, not before phase 1 and not in one commit: extracting crate X = (a) X's files return their own types, (b) the wide `Error`'s own-variants constructed only by X move to X (same commit — research rec 3, no `From<New> for Old` bridge), (c) the wide `Error`'s transparent arms that wrap X's types are **re-pointed** to `ocx_x::…` (they are existing arms, not a shim), (d) `ocx_lib` callers keep using `?` into the wide type. The residue — `error.rs` with only transparent arms — is deleted with `ocx_lib`. Phase 1 touches `error.rs` only in 1.1 (its classify impl leaves) and 1.7 (the `utility` files stop constructing it; `SymlinkWalk`/`InternalFile` sites there use the local types first, because `utility_imports_nothing` must be green before `ocx_util` extracts).

**Feeding `try_classify` (D-048).** `crates/ocx_cli/src/exit.rs` (+ `exit/*.rs`, no `mod.rs` — plan DEC-16) keeps one `classify_error(&dyn Error) -> ExitCode` that walks `source()` and, per node, tries `try_downcast!` in an **append-only list, one line per crate file** (`exit/ocx_oci.rs` exports `pub(super) fn try_downcast(cause) -> Option<ExitCode>` covering that crate's types). Adding a crate adds one line; the 59 entries today become ≤ 17 dispatch lines plus per-crate files. `ClassifyErrorKind` (4 impls) lives in `exit/` too.

**Byte-identity requirement (D-049).** Every user-visible string is a `#[error("…")]` literal moved verbatim, and every wrapper introduced by E1 is `#[error(transparent)]`, so the `{}` top line and the `{:#}` chain of every error are identical before and after. The gate is the acceptance suite (2,412 tests, unmodified). The unit-level guard is **not** a golden of every arm; it is (a) `cargo build` (a deleted arm whose string was needed does not compile), (b) one `display_chain_is_transparent` test per crate that constructs its root `Error` around a fixed inner error and asserts `format!("{err:#}")` equals the inner's `{:#}` (proves transparency, reds when a prefix sneaks in), and (c) the three moved literals that are copied by hand — `FileError`, `PhysicalDialRefused`, `BooleanStringError` — each pinned by a literal-comparison unit test.

## E. `ocx_test_support` design (D-060..D-066)

**The dependency-cycle constraint decides the shape.** The override map must be *read* by the production accessor and *written* by tests in other crates. If the map lived in `ocx_test_support` and `ocx_util` read it, `ocx_test_support` would be a normal dependency of `ocx_util` (shipped). If it lived in `ocx_util` and `ocx_test_support` re-exported the guard, `ocx_test_support → ocx_util` plus `ocx_util →dev→ ocx_test_support` is the sqlx dev-cycle the research rejects, and `ocx_util`'s own tests (`archive.rs:342` uses `test::data`) would sit inside it. Ruling:

1. **The hook lives in the production crate, gated `#[cfg(any(test, feature = "__testing"))]`** (plan DEC-16, superseding the unconditional form): `ocx_util::env::overrides` (`pub mod` under that cfg), i.e. `static OVERRIDES: OnceLock<RwLock<HashMap<String, Option<String>>>>`, `static LOCK: Mutex<()>`, `pub struct EnvLock`, `pub fn lock() -> EnvLock`, `EnvLock::{set, remove, isolate_project_home}`, `pub(crate) fn get(key) -> Option<Option<String>>` — today's `test/env.rs:9–96` with its `#[cfg(test)]` gate widened to the cfg above. `ocx_util::env::var` consults `overrides::get` first under the same cfg (`env.rs:1823–1828` today). Cost in production: none — the table is not compiled. The cross-crate problem (`cfg(test)` cannot cross a crate boundary, research § 5) is solved by the feature: every crate whose unit tests set overrides lists `ocx_util = { workspace = true, features = ["__testing"] }` under `[dev-dependencies]` (resolver v3 keeps dev-dependency features out of the normal build — the release feature-graph check C-078 proves it), and `ocx_cli` forwards `ocx_util/__testing` like every other seam. The compiler is the tripwire: a production use of `overrides::` fails to build.
2. **`ocx_test_support` has zero `ocx_*` dependencies** and holds: `data` (`test/data.rs`; the fixture tree `crates/ocx_lib/test/data/` moves to `crates/ocx_test_support/data/`, `data_dir()` uses the support crate's `CARGO_MANIFEST_DIR`), `fifo` (`test/fifo.rs`, unix-only, `libc`), and `pki` (`tls.rs:664+` `test_pki`, exposing PEM/DER bytes and `serve_https`; callers build `ExtraRoots::from_pem`). It is a `[dev-dependencies]` entry of `ocx_util`, `ocx_oci`, `ocx_config`, `ocx_index`, `ocx_announce`, `ocx_setup`, `ocx_package_manager` (the `data`/`fifo`/`pki` consumers) and nowhere else.
3. `test/manifest_source.rs` (`FakeManifestSource: IndexImpl`, `:17`) is used only by `package_manager/{composer.rs,tasks/inspect.rs,tasks/resolve.rs}` → it becomes `#[cfg(test)] mod test_support::manifest_source` **inside `ocx_package_manager`**; it never crosses a crate.
4. Call-site rewrite: `crate::test::env::lock()` (37 files) → `crate::utility::env::overrides::lock()` in phase 1 (`ocx_util::env::overrides::lock()` after extraction); `crate::test::data::…` → `ocx_test_support::data::…`; `crate::test::fifo` → `ocx_test_support::fifo`; `crate::tls::test_pki` → `ocx_test_support::pki`.
5. **Red-state proof** (the ADR's phase-0.5 validation): `oci/sign/key_ref.rs:688` `read_key_env_bounds_the_value_at_the_shared_cap` sets `OCX_TEST_BIG_KEY` through the override and asserts `KeyEnvError::TooLarge`; with the `overrides::get` consult deleted from `env::var` the read falls through to the real environment, returns `Unset`, and the test reds — deterministically, on every host. The commit that lands the hook shows this red/green pair; the test is named in the phase-0.5 commit body.
6. ~~Structural tripwire `overrides_are_test_only`~~ — dropped (plan DEC-16): under the cfg gate a production use does not compile, so a scanner would guard nothing.

## Rulings I could not make (for the orchestrator)

1. **`BooleanString`'s `clap_builder` dependency in `ocx_util`** — accepted here as a named exception; the alternative (a CLI-side newtype for `ValueEnum`, with `possible` as a const slice) is ~30 lines and keeps `ocx_util` free of clap. Owner call: is one `clap_builder` in an ecosystem-tier crate acceptable?
2. **Tracing-target break announcement** — A.5(i) rules "announce once in the commit subject, no compat". If the owner wants zero user-visible change, the alternative is every crate emitting with an explicit `target: "ocx"`-prefixed constant, which costs a macro wrapper in each crate — I did not design that.

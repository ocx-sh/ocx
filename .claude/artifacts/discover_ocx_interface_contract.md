## Surprises

1. **A typed env seam already exists.** `ocx_util::env` is documented as "the one seam every crate reads the environment through" with `var/flag/string/is_ci` (106 call sites) and a test override table. Real raw `std::env::var*` in production is ~46 sites, not ~111. The design is "route the remaining ~41 + an `EnvVar` declaration into the existing seam", not a new read path. The "111" in the dossier mostly counts seam calls.
2. **The success/error envelope is not schema-described at all.** The `reports` schema documents the `data` payload of the 6 envelope roots only; `ErrorEnvelope` has no `JsonSchema`. Contract scope "stdout error envelope ... schema-described" needs a new schema kind and a `JsonSchema` derive; there is no 8th kind to extend. Also errors print compact, reports pretty.
3. **Success envelope: 6 of 56 roots (5 of 55 impls)**, and the dossier's 55/56 root count is two different units (impls vs published roots).
4. **Code and ADR disagree on envelope bump rules** (see Prior decisions). The dossier's "new enum variant = additive" matches the code comment, contradicts ADR Amendment 9.
5. **A clippy ban will not work by dropping in `clippy.toml`.** rules_rust's default `clippy.toml` label is a stub; the file must be wired by `--@rules_rust//rust/settings:clippy.toml=//:clippy.toml`. `rust-cargo.md` LINT-09 already mandates the file, `rust.taskfile.yml:53` already lists it as a source, yet it does not exist. The existing `workspace_structure.rs` ratchet pattern (`ssrf_guard_ratchet`) is a Bazel-independent alternative.
6. **`OCX_CEILING_PATH` is read in production and documented nowhere**; 16 documented `OCX_*` names are outside `env.rs`; `OCX_TEST_FAULT*` is an ungated test hook in `ocx_project` shipped in release builds with a non-`__` prefix; three spellings of "internal" coexist. The "undocumented env var" failure the owner cited is reproducible today with these.
7. **Semantic breaks are invisible to a schema diff**: `737a66052` (`fix(push)!`) changed only a description. The compat gate (shape only) cannot see it; the ledger needs a manual path or the gate needs description/enum-value checks.
8. **Release baseline is shallow**: goldens first exist at `v0.6.3`; `v0.6.3` -> `v0.6.4` changed all 7 goldens (631+/399-). A gate baselined at `v0.6.3` would have needed many entries; the dossier's "baseline = last release tag" starts at `v0.6.4` only after phase 1 cleans the tree.
9. **`reports` golden is far from the codegen subset**: 3 true untagged `anyOf`, 41 nullable-`anyOf` plus 51 `type:[T,"null"]` (two nullable forms), 15 non-const `oneOf` unions (tag keys not checked), 260 of 684 properties without own description. Python SDK's handshake does not use JSON or any schema version, so the "terraform-exec" handshake over `version --format json` is new there, and `VersionData` has no schema/contract field (`api/data/version.rs:25-32`); only `version` is guaranteed present.
10. **ocx-mirror shells out in 6 places, not 3**: `create`, `lock_derive` (`package pull`) and `python_push` besides push/sign/announce; it links 8 ecosystem + 1 interface crate; its copied `PushReport` is deliberately "every field defaults" tolerant, so replacing it with a strict generated type changes its failure mode (an older `ocx` would now fail instead of reporting zeros).
11. **Python SDK is already stale on exit codes** (missing 87) and pinned two releases behind (0.6.2 vs 0.6.4): evidence for the registry-from-`ocx_exit` requirement.
12. **`ocx_schema` is internal tier**, so the generator "next to it" inherits no stability promise; and `ocx_mirror` may not link it. Re-tiering is an ADR decision, not a given.
13. **`-c`, `-l`, `-g` collisions are real** and one (`-g`) carries an explicit "do not unify" comment; `command/deprecated.rs` `RENAMED` holds 3 pairs (+ the flag carved out), matching CLAUDE.md's four.

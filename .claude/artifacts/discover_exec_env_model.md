## Surprises

1. **The ledger and the projection sit on opposite sides of a crate edge.** `Ledger`/`__OCX_ENV_STATE` codec is in `ocx_shell` (depends on `ocx_package`, `ocx_config`); `apply_ocx_config`/`Env`/`OcxConfigView` are in `ocx_config` (`scripts/crate_map.toml:31,38`; `ledger.rs` imports `ocx_package::metadata::env::{Entry, ModifierKind}`). A single state type read by the projection and by the hook has to move below `ocx_config`/`ocx_package` (or be split into policy half low, applied-values half high). Both `ocx_env` and `ocx_config` are ecosystem crates, so the move carries the same-series lockstep consumer obligation.
2. **`unset OCX_PROJECT` is load-bearing, not vestigial.** `check_global_project_exclusivity` (`context.rs:1058-1070`) exits 64 for `--global` plus an exported `OCX_PROJECT`. Every `--global exec` trampoline (and old ones already on disk, and the Windows `.exec` strip) depends on the unset. Removing only the `OCX_GLOBAL` env form leaves this unchanged; dropping the unset needs the exclusivity rule changed to "explicit flag beats env" first. The dossier's proposed test ("baked `--project` beats `OCX_PROJECT`") tests the wrong half (flag already wins, `loader.rs:494-501`).
3. **Today's default `ocx exec` already is the proposed `--isolate`** (revert hook contribution, keep OS/user env), while `launcher exec/shim` re-entry already layers (`Env::new()`). Making layer the default flips `exec`/`package exec`/`package test`/`patch test`/`shell`, changes `product-context.md:62` and the "Hermetic `ocx exec`" doc sections, and makes launcher re-entry and `ocx exec` finally agree.
4. **`trampoline_ocx_binary` is not the pin rule.** It returns the installed path whenever it exists, even if a dev build is running; reusing it as-is for `OCX_BINARY_PIN` would point acceptance tests, Bazel and dev builds at the installed binary (the incident `adr_package_entry_points.md:994` describes). The pin needs a new "is the running exe the installed one" test (canonical compare).
5. **#678 is `OCX_GLOBAL`, not `OCX_PROJECT`.** The hook honours `OCX_PROJECT` already (through the loader's own env read) and never consults `global`. Requirement 3's "honour `OCX_PROJECT` identically" is already true; the fix is removing the `OCX_GLOBAL` env form (plus `shell allow` refusing nothing odd). Separately, `OCX_PROJECT` is *cleared* for children by `apply_ocx_config` (unreleased, ed5f17f8); the dossier does not say whether the projection keeps clearing it, and "nesting should simply work" (`a` then `b`) depends on it.
6. **`OCX_HOME` is written by the env shims into every login shell and read by generated files** (Windows shim containment, rc block, `env.*`), so "public `OCX_*` are never written into emitted shell code" is false today and cannot be made true for `OCX_HOME` without rewriting the setup shims; the "verify no generated file reads it" check from the dossier fails (shim, rc block, env shims).
7. **`RETIRED` cannot express this removal as designed**: a mandatory `replacement: &EnvVar`, and `Status::Removed` makes ocx refuse to run (exit 78) when the name is set. A `Removed` row for `OCX_GLOBAL` re-creates the leak as a hard failure; only a `Window` row warns, and windows are tied to `REMOVAL_RELEASE` 0.7.0 with "removal above crate version" enforcement.
8. **No compat baseline exists yet**, so `--stack`, `OCX_GLOBAL`, `__OCX_EXEC_SCOPE`, the three plumbing vars and the `stack` record field can all be removed before the first rotation with no ledger entry. The ledger step in the dossier's Open Questions is moot if this ships before the first release containing `cli.json`; the `ocx-sdkgen` output (`env.rs` golden) still changes.
9. **The widened carrier changes the security posture the overhaul ADR rested on.** Today the carrier names only what to revert (L-1/L-2, forgery rules a-c); adding *policy* (`offline`, `frozen`, `no-consent`, `config`, `index`, `mirrors`, `patches`, `toolchain dir`) makes an unauthenticated variable an input to consent and resolution. A-06 ("trusted at the privilege level that set it") needs re-ruling; today `OCX_NO_CONSENT`/`OCX_OFFLINE` as ambient vars have the same trust, but the state is a second, less visible channel. A-38 also forbids the size warning proposed in the dossier.
10. **The SDK spawner cannot adopt "one projection function"** (generated template, no `ocx_*` deps) and deliberately scrubs *user* `OCX_*` (`spawn.rs:36-57`); sibling generated SDKs (`ocx-sdk-python` per overhaul ADR) hold the same scrub. The "two variables" rule needs a spec the generated runtimes can implement independently, and a conformance fixture.
11. **Pin staleness in the hand-off.** `run_handoff` (self-update) inherits the full env, including the parent's old pin and policy; a design that declares `OCX_BINARY_PIN` "frozen, follows upgrades" must decide this spawn too.
12. **Execution scope marker for `--global exec` is `$OCX_HOME`** (9a), so the global-exec shell is never "pinned" under today's yield rule; in the new model `__OCX_ENV_STATE` session selection must name the global tier explicitly rather than a directory.

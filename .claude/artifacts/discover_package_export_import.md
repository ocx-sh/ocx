## Open checks

1. **Index source for import.** `ocx index update` and `sync` loop over the configured index sources (`crates/ocx_cli/src/command/index_common.rs:97-120`, `refresh_each`). Each takes the first source whose jurisdiction covers the identifier, wraps it with `Index::from_source` (`crates/ocx_index/src/lib.rs:168`) and calls `LocalIndex::refresh_tags(identifier, &source)`. An `OcxIndex` can be built in memory: `OcxIndex::new(OcxIndexConfig)` at `ocx_index.rs:570` takes a base URL and a transport, and `FileIndexTransport` serves any directory. Not verified: that `OcxIndexConfig` accepts an injected `FileIndexTransport` without passing `resolve_base_url`. The `file://` base needs an empty authority and an absolute path (`ocx_index.rs:458-474`). `index sync` enumerates through `OcxIndex::fetch_catalog_strict` (`ocx_index.rs:994`). `refresh_published` reads the dispatch objects through the source, so the export needs `o/`.
2. **A catalog for a partial export.** Layout: `index/<source>/config.json`, `c/index.json`, `p/<ns>/<pkg>.json` (root document), `p/<ns>/<pkg>/o/<algo>/<hex>.json` (dispatch objects only). A catalog listing a subset is valid for the local reader: `list_local_repositories` (`local_index.rs:584-594`) returns the catalog keys for a published source. Over `file://`, `fetch_catalog_strict` treats a missing `c/index.json` as an error. So import's "every tag in the export" path needs `c/index.json`; the per-package `refresh_tags` path does not.
3. **`ocx package copy` from a blob directory.** `OciTransport` is sealed (`crates/ocx_oci/src/client/transport.rs:256`); implementors are `NativeTransport` (`native_transport.rs:382`) and `StubTransport` (`test_transport.rs:201`). Methods: `pull_manifest_raw` :284, `pull_blob` :291, `pull_blob_to_file` :294, `pull_blob_streaming` :314. Copy reaches `self.client.transport()` at `copy.rs` :161/:165/:237/:326/:370/:432. The narrowest seam shared by pull's layer read and copy's source read is a wrapper transport inside `ocx_oci` that answers `pull_blob_streaming`, `pull_blob` and `pull_manifest_raw` from the lookup chain before delegating. Pull's metadata path reads through `ChainedIndex::fetch_blob` and its content-store seam, which a transport wrapper alone does not cover. Not verified: whether copy re-hashes a streamed blob.
4. **`PathList` on Windows.** Parsed with `std::env::split_paths` throughout: `ocx_config/src/loader.rs:200` (`OCX_CONFIG`), `ocx_cli/src/app/context.rs:126`, `ocx_config/src/shell.rs:666`. On Windows the separator is `;` and `"` quotes an entry. One outlier, `ocx_config/src/env.rs:264`, splits on `;` by hand; not read.
5. **Names.** Existing env vars near the topic: `OCX_OFFLINE`, `OCX_INDEX`, `OCX_MIRRORS`, `OCX_RECORDS_DIR`, `OCX_TOOLCHAIN_DIR`, `OCX_CONFIG`. Existing flags: `--offline`, `--index`, `--remote`, `--frozen`, `--records-dir`, `--config`, `--export-file`. No env var or flag contains `blob`, `cache`, `depot` or `source`; `--no-cache` exists on sign and verify. "export" is already used by `ocx env --shell` / `--ci` / `--export-file`, `ocx direnv export`, and the telemetry export. IC-13: an env name is `OCX_` plus the long flag in SCREAMING case. IC-12: an output destination is `--output`/`-o`.
6. **`blobs/` assumed to hold small JSON.** `BlobStore::read_blob` has no cap, and `ChainedIndex::fetch_blob` returns `Vec<u8>` and hashes in memory. Its callers read manifests, configs and image indexes. One exception reads a layer into memory: `patch_discovery.rs:1129`. Garbage collection classifies any `data` file in a valid CAS directory and is size-blind (`blob_store.rs:159-168`). A layer archive in a home-shaped tree is collected unless something references it.
7. **Atomic writes.** `ocx_util::fs::persist_temp_file` (`ocx_util/src/fs.rs:134`), `persist_temp_file_if_absent` (:142), `persist_temp_file_noclobber` (:160), all `NamedTempFile::new_in(parent)` and blocking. No hash-while-write helper exists (`HashingAsyncReader` is read-side). The streaming pull never writes the compressed archive to disk. `temp/` is per-home.
8. **Referrers.** Code in `crates/ocx_sign/src/sign/referrers.rs`, `verify/pipeline.rs`, `sign/state.rs`. Capability cache at `state/referrers/<registry>.json`. Not verified: where referrer manifests are stored locally and the local-first read.

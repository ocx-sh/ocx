## 4. New findings

### N1 [Warn] `crates/ocx_lib/src/package/cascade.rs:324` + `crates/ocx_lib/src/publisher.rs:282-291` — the addressing inversion left `push --cascade` reading its tag list from a mirror and its blocker manifests from the canonical host

**Actionable.** The inversion in `20fab614` was scoped deliberately: `Publisher::list_tags` was pinned back to `Mirrored` with the reason "Moving it changes every push", while `has_blocking_platform` inside the *same* `push_cascade` flow was allowed to inherit the new canonical default (`crates/ocx_lib/src/package/cascade.rs:324` — the explicit `fetch_manifest_addressed(…, Canonical)` was replaced by the unaddressed short form). The result is one decision made from two hosts.

Concrete failure: prod publishes `3.29` for `linux/amd64`, so `latest` must not move when `3.28.1` is pushed. A mirror that lags and does not list `3.29` means `parse_versions` never yields it, so `has_blocking_platform` is never asked about it at all — and the canonical blocker fetch it would now have used is unreachable. `latest` moves backwards.

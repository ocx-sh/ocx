## 2. The managed tier

Defined by `.claude/artifacts/adr_managed_config_tier.md` (Accepted, deciders `@michael-herwig`, architect, Round-1 review panel; 2026-07-04; header at `:97-103`). v2 amendment `:5-90` made it config-as-package (`2ed7b5d2`). Plan: `.claude/state/plans/plan_managed_config.md` (not on disk in this worktree).

Problem (`:105`): "Corporate/platform teams want a baseline ocx config (mirrors, patch-registry pointer, default registry) distributed to every workstation/CI runner, refreshed centrally. Channel = OCI registry ocx already uses." Exactly one artifact per host.

Decision drivers (`:109-116`): C1 compose with existing `Config::merge` fold; C2 "Refresh never blocks a normal command; network fetch only on explicit action"; C3 `required=true` fails closed on local disk state; C4 CI ephemeral mode, no separate code path; C6 "Remote payload can never redirect/loosen the tier that fetched it (one-hop)".

Mechanics that matter for injection:
- Position: "managed snapshot = 4th existence-checked discovery candidate, slot after `home_path()`, below `OCX_CONFIG`/`--config`. Zero network in loader." (`:123`). Merge order "base → payload → overlay" so explicit-tier values still beat payload.
- `OCX_MANAGED_CONFIG` (`:128-131`): "env read first, overrides `config.managed.source` for this invocation only, never written. `self setup --managed-config` = only writer". "Runtime `OCX_MANAGED_CONFIG=""` = unset (matches `OCX_CONFIG=""` precedent)". Fetch on demand at load "NEVER acceptable (C2), CI included: CI recipe = `OCX_MANAGED_CONFIG=... && ocx config update && ocx <cmd>`".
- `OCX_NO_CONFIG=1` "suppresses the candidate AND disables the `OCX_MANAGED_CONFIG` env-override read (hermetic means hermetic)" (`:126`). Current wording in `crates/ocx_env/src/vars.rs:64-73`.
- System-locked source cannot be redirected by flag or env (exit 78): `2ed7b5d2` body.
- Identity gate: snapshot merges only if provenance source equals effective source; "CI cache-poison defense" (`:123`, `:162`, `:281`).
- Strip rule (Decision I, `:180-182`): `[managed]` in payload is stripped with a warning, one hop only. "All other sections merge normally; loosening structurally blocked by G."

Trust model, as stated:
- "Trust root = operator's registry (same as [mirrors]/[patches] today); unsigned-but-digest-verified v1 = deliberate deferral to `[trust.policy]` #98 / auto-verify #99" (`:295`). "blast radius of compromised config registry = fleet-wide [mirrors]/[patches]/[registry] control — mitigations: digest-pin bootstrap, registry push-protection, registry/mirror system locks". "`state/` snapshot user-writable = same local trust level as config.toml itself". Also the CWE-345 note: the gate "is not a defense against an attacker who already has local write access to `$OCX_HOME`" (`:79-83`, v2 amendment).
- Who may set the source: the seed in `$OCX_HOME/config.toml` or the env var or `--managed-config`; a system-tier source locks it. Hostile parent env is treated as out of scope (same posture stated for consent vars, `adr_shell_env_overhaul.md:350`).
- What the payload may override: everything outside `[managed]` merges normally, except where a lower (system) tier locked it. 2026-07-31 amendment: unknown keys ignored fleet-wide so an older binary does not drop the whole payload.
- Amendment 2026-08-19 (`:307-334`): `trusted_root_json` from managed tier honoured "only when the `[managed] source` seed is digest-pinned"; path-form `trusted_root` always ignored with a warning ("a fleet payload cannot name a path on someone else's machine").
- Amendment 2026-08-23 (`:336-391`): "keep the union; do not carve the managed tier out of `insecure`" — residual recorded: "A managed-config publisher — compromised or malicious — can still self-authorize plaintext transport for any host the system tier has not already locked". Rationale: "`[managed]` is sold on fleet-wide policy distribution".
- Amendment 2026-09-13/15 (`:392-471`): `extra_ca_certs_pem` honoured from an unpinned managed source; path form stripped; then system-scope lock added (`c9a0dfb6`, `adr_managed_config_tier.md:459`).
- Mirror posture (`:184-186`): the managed fetch is mirror-rewritten but its map derives "from local tiers only"; "payload can never influence its own refresh route".

Explicitly left out:
- No network fetch inside the loader (Opt 1 two-pass "REJECTED — violates C2").
- No CAS blobs or GC roots for the snapshot (Decision D, "Opt 1 ... REJECTED").
- No `toml_edit` dependency for the seed write at v1 (Decision C; later `toml_edit` is used in `ocx config push` inlining, `:307`).
- No downgrade monotonicity: "any digest change accepted incl. rollback — documented known limitation" (`:295`).
- No console, no reporting: website says "Deliberately pull-based and console-free: fleet visibility is `ocx config update --check --format json` in existing inventory tooling" (`.claude/rules/product-context.md:81`, differentiator 11).
- A gap the SOTA review raised: no local diagnostic verb, A1 in `.claude/artifacts/research_oci_config_artifact.md:83` (later filled by `ocx config update --check`, `adr_managed_config_tier.md:194-196`).
- Keys it does not carry: nothing about telemetry or tracing; its keys at ADR time are `[registry]`, `[registries]`, `[mirrors]`, `[patches]`; later additions `[records]`, `extra_ca_certs_pem`, `[trust.*]`, `[shell]`.

## 3. Multi-file config, include, drop-in, list-valued paths

There was a recorded rejection of `include` and drop-in directories, and none for list-valued path variables.

- Deferred indefinitely, 2026-04-12: `.claude/artifacts/research_configuration_patterns.md:73-91` ("Deep Dive 3 — `include` Key"): "Strong recommendation: defer indefinitely. The multi-tier model already provides layering for free." Reasons, verbatim: "1. Multi-tier solves the same problem. System → user → OCX_HOME + `OCX_CONFIG` covers every real composition need OCX has." "3. Wrong target audience. OCX is automation-first; CI uses `OCX_CONFIG` to a single explicit file. `include` is a human-ergonomics feature." "4. Drop-in directories (`config.d/*.toml`) are even lower value for OCX — they solve coordination between many uncoordinated contributors, which OCX doesn't have." Cycle detection, relative paths, error attribution, recursion limits named as cost.
- Same in the plan: `.claude/artifacts/plan_configuration_system.md:159-161` "`include` key — DEFERRED INDEFINITELY." plus a pre-agreed shape if ever needed: "array of `{ path, optional }`, paths relative to including file, including file wins, no globs, cycle detection" (research `:85-89`). Changelog row `plan_configuration_system.md:624`.
- The 2026-04-12 reasoning assumed "CI uses `OCX_CONFIG` to a single explicit file". The managed tier (2026-07-05) later became the answer to "patch an environment centrally" without multi-file config: one OCI artifact, one `config.toml`, merged as a tier.
- Closest precedents for a list-valued env variable (not for config files): `OCX_CONSENT_PATHS` "OS PATH-separator list, mirroring `MISE_TRUSTED_CONFIG_PATHS`" and `OCX_CONSENT_NAMESPACES` comma-separated because ":" collides with a registry port (`adr_shell_env_overhaul.md:350`, 2026-08-24). Both "additive: unioned with the config tiers, never a replacement". Empty-token rule: "drop every empty token before any `ScopeSpec` is constructed" (same line, next bullet). `OCX_INSECURE_REGISTRIES` and `OCX_MIRRORS` are also list-shaped env inputs (`configuration.md:270`, `:121`).
- Searched and found none: any ADR, plan, discussion or commit proposing `OCX_CONFIG` as a path list, config-file globbing, or a `config.d` directory (negative below).

## 4. Merge semantics: append vs replace

Recorded decisions, by key class:

- Default fold (research, 2026-04-12): "Cargo model — scalar nearest-wins, tables merged key-by-key, `[patches]`-style atomic sections replaced wholesale, env vars beat all files" (`research_configuration_patterns.md:15`). Named-table over array rationale: "uv's `[[index]]` array model loses on multi-tier merging: arrays cannot be surgically overridden by a higher tier; the entire array must be re-specified" (`:30`); plan `:187` "Named registry tables over arrays ... Enables surgical override".
- Anti-pattern listed at that time: "Deep merge (surprising partial overrides)" (`research_configuration_patterns.md`, Anti-Patterns).
- `Config::merge` had no array-append arm until the trust ADR: `.claude/artifacts/adr_trust_policy.md:264-275` (Proposed 2026-07-09, #98): "D3 — Tier merge: array-APPEND (union pool), never replace ... there is **no** array-append precedent in `Config::merge` today — every current arm is scalar-wins or table key-merge; this is a deliberate new merge rule". Shipped as documented: "Unlike every other section, trust policies **array-append** across the `config.toml` tiers rather than replace" (`website/src/content/docs/reference/configuration.md:448-449`). Cross-tier rule: operator set is authoritative over project `ocx.toml`; project can add trust for ungoverned scopes, never weaken.
- Consent (`[shell.consent]`): union across tiers, no tier overriding ("following git"). The earlier claim "union, never override, no precedence logic" was corrected in `adr_shell_env_overhaul.md:349` ("The earlier flat ... claim is corrected here: it was true only of a list of bare prefixes"). Exception A-40: a refused `[shell.consent]` carrying `namespaces.exclude` from home/system/`--config` tiers exits 78 rather than being stripped, because stripping `exclude` "leaves that `include` standing unopposed, which **widens**" (`plan_shell_env_overhaul.md:285`; `adr_shell_env_addenda.md:1664`).
- `[mirrors]`: replace per host and role; env `OCX_MIRRORS` overrides per host and role, "a role it omits still comes from `[mirrors]`" (`configuration.md:119-121`).
- `[registries.<name>].insecure`: union with `OCX_INSECURE_REGISTRIES`, except a system-tier `insecure = false` locks the host shut (`configuration.md:270`; `adr_managed_config_tier.md:353-375`). Property stated as worth keeping: "no source can take a host back out of the set, so there is no four-way truth table".
- System lock: a locked system value ignores every lower tier including the managed payload (`adr_managed_config_tier.md:171`).
- Bug / reversal found:
  - `1c99ef4c` (2026-07-26): "A system-scope `[registries.<name>]` lock was a no-op: `Config::merge` reaches entries via `map.entry(name).or_default().merge(..)`, so the system tier is never `self` on the fold that carries it in and the flag was dropped." Both `RegistryConfig::merge` and `MirrorConfig::merge` now adopt the lock from `other`.
  - Decision I's claim "loosening structurally blocked by G" was found untrue for `[registries.<name>]`: `adr_managed_config_tier.md:343-349` ("it was never true for `[registries.<name>]`, and `insecure` is what turns that gap from theoretical into exploitable").
  - `adr_managed_config_tier.md:150` / v2: `deny_unknown_fields` dropped (parse-level reversal of the typo-protection stance).
  - `1c99ef4c` also: explicit `[mirrors."<ns>"]` entry suppresses the compiled-in index; the suppression lives in `Context::build_index_sources`, not `ConfigLoader`, because "the loader never reads `OCX_MIRRORS`".

## 6. CI telemetry

Commits (all `ci`, `fix(ci)`, `docs(ci)` or `feat(telemetry)`), destination `https://otel.ocx.sh` (nginx in front of Tempo, Grafana dashboards in a separate `server-hetzner1` repo per `.claude/rules/subsystem-ci.md:~192`):

- `520e4623` (2026-09-20) "ci: per-test timing from every unit and acceptance run lands in Tempo behind otel.ocx.sh". Exports JUnit as OTLP traces via `junit2otlp` 0.1.2 (composite action `.github/actions/test-telemetry`; local `telemetry:push` in `taskfiles/telemetry.taskfile.yml`). Resource `service.name=ocx-tests`; attributes `ocx.suite`, `ocx.source`, `ocx.os`, `ocx.git.{sha,branch}`, `ocx.ci.{run_id,job}`, `host.name`. Lessons in body: "Its exit status says nothing. Export errors go through the OTel error handler, so a push that lands nowhere still exits 0"; "The endpoint must carry a scheme ... a bare `host:port` fails with `dns resolver: missing address`" (gRPC only; no HTTP exporter); "the figure the dashboards need is the `tests.case.duration` attribute, in milliseconds, never the span's own duration". Failure policy: "Telemetry never decides a job: every push step is `continue-on-error` with a five-minute timeout". Fork PRs: `env.OTEL_OTLP_AUTH != ''` skips, "the shape the sccache credentials already use". Local: "Off by default locally, and silently: with no `~/.config/ocx-telemetry/env` and no `junit2otlp` on PATH the task prints nothing and changes nothing."
- `22e8714d` (2026-09-20) docs: "junit2otlp reads stdin with a 1 MB-per-line scanner, and pytest writes its report on a single line: 545,175 bytes ... Past the ceiling the tool exits 1 with `bufio.Scanner: token too long` and pushes nothing".
- `acb68763` (2026-09-20) "every test of a run reaches Tempo, not the 31% two OTel defaults allowed": (a) the 1 MB line cap; (b) BatchSpanProcessor queue default 2048: "a span enqueued above that is dropped with no log line, no error and exit 0. Measured: the 8,215-case unit report landed 2,560 of its 8,250 spans." Fix: re-emit one element per line; size `OTEL_BSP_MAX_QUEUE_SIZE` from the report; `--batch-size 512` ("One run at the default lost a contiguous batch of exactly ten spans mid-report, unreproducibly and with nothing logged"). "found by counting spans rather than by reading the tool's output". Endpoint stays `https://otel.ocx.sh:443`; Cloudflare proxy rejects gRPC for the zone (noted as not this repo's decision). Credential: nginx basic auth, user `ci`.
- `454fa243` (2026-09-20) docs: "`tests.suite.total` ... is a metric name, passed once to `createIntCounter` and never placed on a span ... nothing a span carries says how many were meant to arrive"; counting must hold Tempo's count against the `<testcase>` count "from outside".
- `44c950ab` (2026-09-22) feat(telemetry): `scripts/bep_to_otlp.py`, Bazel BEP to OTLP/HTTP JSON (`service.name=bazel-build`, spans `bazel.target`, `bazel.kind`, `bazel.success`, `bazel.cache`, `ocx.source`, `ci.run_url`). Lessons: "No span carries a credential. Bazel serialises the whole client environment and every rc-file flag value into the stream — measured on this host, 276 `--client_env` entries with both AWS keys among them and nine `--remote_header` values. The reader has an allowlist, not a denylist"; "The reader has a floor ... '0 targets' otherwise exports green"; "The transport refuses a redirect. OTLP/HTTP defines none, and urllib's default opener replays the `Authorization` header at the target"; "Failure is loud on stderr and never fatal". Policy detail in `subsystem-ci.md:188-199`: "The only sanctioned silent exit is an unset endpoint"; because HTTP is synchronous "the queue-drop budget that dominates the JUnit half does not exist here"; "The credential is process-scoped on this half".

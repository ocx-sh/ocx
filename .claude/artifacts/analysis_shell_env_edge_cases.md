# Edge-Case & Known-Case Register — Shell Environment Overhaul

Companion to [`adr_shell_env_overhaul.md`](./adr_shell_env_overhaul.md). Every row
is a case the reconciler, the per-shell emitters, the consent predicate or the
runtime environment can put the design in, written so that a test author needs no
further design work: the trigger is a reproduction, the expectation cites the
decision it follows from, and the tier says where the check belongs.

**234 rows.** Produced by four parallel adversarial passes over the ADR and the
shipped code — reconciler semantics, per-shell mechanics across ten `Shell` arms,
consent/trust/config, and operational/environmental. `review_adr_env_sota.md`'s
G-1..G-6 are folded in as `known` rows rather than rediscovered. Twelve
cross-worker duplicates were removed. Three further rows (`EC-HOOK-015`,
`EC-HOOK-016`, `EC-PROC-015`) were added by WP-15 for Discovery corrections 12,
15 and 14 (`plan_shell_env_overhaul.md` §5), which the four adversarial passes
did not surface. Two more rows (`EC-GRANT-020`, `EC-GRANT-021`) were added
2026-08-31, correcting EC-GRANT-010's premise once the git `/*` subtree form for
`safe.directory` was confirmed shipping (not absent) and `paths` gained the
matching grammar. Three further rows (`EC-GRANT-022`, `EC-GRANT-023`,
`EC-GRANT-024`) were added the same day, round 2, for tilde expansion, the
release-enforced canonical-`project_dir` refusal, and the never-matching-entry
diagnostic `ocx shell state` now reports. Two final rows (`EC-GRANT-025`,
`EC-GRANT-026`) were added 2026-09-01, round 3, pinning what the entry-side
comparison folds per platform and the fact that the grammar has exactly one
wildcard.

## How to read a row

| Column | Meaning |
|---|---|
| `ID` | Stable slug. Downstream tests reference it; never renumber. |
| `Known/Edge` | `known` — the ADR or the SOTA review already names the case. `edge` — derived here. |
| `Trigger` | A reproduction, not a description. Exact starting state, exact mutation, exact observation point. |
| `Expected behaviour per ADR` | The outcome plus the decision it follows from. `UNSPECIFIED-BY-ADR` where the ADR is silent — every one of those carries a recommendation, collected at the end. |
| `Test tier` | `rust-unit` (pure function, no process) · `pytest-hostshell` (a real shell on the host runner, no pty) · `pytest-shellzoo` (the Docker image, all nine shells; `tier 2` = eval-the-snippet, `tier 3` = real pty) · `manual-only` (with its justification in the cell). Two tiers named with `+` means the row yields two checks — a pure-string assertion and a live proof — and the first is primary. |
| `ADR ref` | Decision number and/or ADR line range. |
| `Coverage` | A test that proves the row, as `<file>::<test>`. Filled from the test tree, never by hand. **A sample, not an index**: the cell names *a* covering test, never every one — `reconcile/fingerprint.rs` holds 13 tests and is cited by 2 rows. Read it as "this row is proven here", never as "this is all the coverage there is", and check the tree before deleting a test because no row names it. |

**Coverage: 234 / 234 rows cited, 231 by a test that asserts** — 133 by a pytest
test in `test/tests/test_shell_reconcile*.py`, 105 by a Rust `#[test]` under
`crates/`, 4 rows by both (133 + 105 − 4 = 234). Five rows are tiered `manual-only`
and two more carry a `manual-only` half; each cites a documented
`manual_procedure_*` function instead of an executable check, and each states the
obstacle that earns the tier rather than merely asserting one.

**Three rows are cited only by a placeholder**, and are named as such: they carry
the register's own `uncovered` vocabulary and are pinned in `_UNCOVERED_ROWS`
(`test/tests/test_shell_reconcile_edge_cases.py`), so a fourth cannot join them
quietly. None of the three waits on a platform: `EC-FP-005` needs a runtime seam
for `CARGO_PKG_VERSION`, and `EC-VER-003` / `EC-VER-007` each need two staged
builds carrying different `Plan` schema versions. Every count in these two
paragraphs is recomputed from the parsed register by
`test_traceability_the_summary_counts_match_the_register`, because a number
nothing checks is how `91` stood here while the tree said `90`. A citation from a body that runs no assertion is
the state a test that never ran is in, which is why the gate refuses to accept one
as a row's *only* coverage unless the row is on that pinned list.

**The column is a gate, not a claim.** `test_traceability_every_register_row_is_cited_by_a_real_test`
reds when a row is cited by nothing, and when a coverage cell names a test that
has stopped citing it. Only a real `#[test]` / `def test_*` counts: moving an id
into ordinary prose reds the gate even though the id is still in the file. Two
sibling checks close the loop the other way — every `pytest`-tier row must name a
test in the edge-case module, and every test in that module must trace to a row
that exists.

**Tier distribution** — `rust-unit` 123 · `pytest-hostshell` 75 ·
`pytest-shellzoo` 31 · `manual-only` 5, each row counted once by its
first-listed ("primary") tier. "Needs a Windows runner leg" is *not*
`manual-only`: the ADR's Validation §Windows already commits to that leg, so
those rows are `pytest-hostshell` on it. `manual-only` is reserved for the five
cases no runner can construct — a filesystem with coarse mtime granularity, a
real interactive ConPTY session under Windows PowerShell 5.1, a real IDE
process, a genuine multi-user privilege boundary, and a fix that reaches
outside this package's own files (`shell/reconcile.rs`'s carrier).

**Known/Edge** — 140 `known`, 86 `edge`.

**The addendum binds.** [`adr_shell_env_addenda.md`](./adr_shell_env_addenda.md) closes
every `UNSPECIFIED-BY-ADR` row below and overrides the rows carrying an addendum-override
or register-error marker. Where a row and a resolution disagree, the resolution is the
specification.

**Tier vocabulary.** This register's `Test tier` column names the **harness**
(`rust-unit`, `pytest-hostshell`, `pytest-shellzoo`, `manual-only`); the ADR's Validation
section names a **cost ladder** (Tier 1 no shell / Tier 2 execute the emitted snippet, no
pty / Tier 3 a real pty). They correspond: `rust-unit` → Tier 1, `pytest-hostshell` →
Tier 2, `pytest-shellzoo` → Tier 2 in the shell-zoo image (Tier 3 for a row that needs a
prompt to fire), `manual-only` → outside the automated ladder. The three `manual-only`
rows — `EC-FP-002`, `EC-PROC-011`, `EC-PROC-013` — are a stated residual, not an omission.

**Eight dangling ids.** `EC-PATH-009`, `EC-PATH-011`, `EC-PATH-012`, `EC-HOOK-012`,
`EC-IDENT-005`, `EC-FS-009`, `EC-FS-011`, `EC-SIZE-001` are referenced in other rows'
prose but exist as no row in this register — leftovers from removed duplicates. A reader
chasing one is chasing nothing; no rows are added for them and nothing is renumbered.

## Coverage gaps in `test/tests/test_shell_activation.py` today

The file is a good foundation and the ADR is right to extend it rather than start
over — it already owns the shell-zoo matrix, `_script_pty_command`'s util-linux/BSD
split, and a `_clean_env` that keeps assertions non-vacuous. But its subject is one
bug class, and almost nothing in this register is reachable from it.

**What it actually asserts.** `_assert_activation`
(`test/tests/test_shell_activation.py:121-137`) is the only environment assertion in
the file, and it checks exactly three things: the shell exited 0, no `env.*`
"no such file" appeared on stderr, and the ocx bin dir appears **exactly once** on
`PATH` after a double source. That last one is the whole of the file's overlap with
this register — it is `EC-LIST-001` (idempotent `move_to_front`) and nothing else.

| Gap | Where it bites | Evidence |
|---|---|---|
| **No per-prompt anything.** The file models shell *startup* only. `PROMPT_COMMAND`, `precmd`, `fish_prompt`, the pwsh `prompt` function and `env_change.PWD` appear zero times. The double source at `:121-137` proves startup idempotence, not a reconcile. | Every `EC-HOOK-*` row, `EC-FP-*`, `EC-SCOPE-003/004`, the whole ADR Validation tier 3. | `grep -c PROMPT_COMMAND\|precmd` = 0; the pty helper `:281-299` is used only at `:304`, `:360`, `:409` to satisfy elvish's and pwsh's interactive-rc sourcing — it never produces a prompt. |

**Consequence for planning.** Only `EC-LIST-001` is covered today. Of the 220 rows,
112 are `rust-unit` and need a module that does not exist yet
(`ocx_lib::shell::reconcile`); the 105 shell-level rows need a second acceptance

gaps above are why "beside" rather than "inside": this file's fixtures (no project,
one command, `PATH`-only assertions) cannot host them without being rewritten into
something else.

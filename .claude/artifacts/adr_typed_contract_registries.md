# ADR: Typed, compile-time-checked contract registries

## Metadata

**Status:** Accepted
**Date:** 2026-10-04
**Deciders:** Michael Herwig (owner: "do it in the current PR — I love structured, compile-time checked data")
**Related PR:** [ocx-sh/ocx#580](https://github.com/ocx-sh/ocx/pull/580)
**Domain Tags:** api, integration
**Amends:** [`adr_crate_split_workspace.md`](./adr_crate_split_workspace.md) rows E3/E4 (D2 below); [`adr_ocx_interface_contract.md`](./adr_ocx_interface_contract.md) is unchanged — every wire byte stays.

## Context

The machine-interface contract work (PR #580) declares its registries as strings and parallel tables held together by tests, several of which parse Rust source text with `syn` or regex. Three read-only audits (2026-10-04) found:

- **Error classification.** One error variant's slug, exit code and summary are written three times — a `classify` match arm, a `DETAILS` row (`details!`, `crates/ocx_cli/src/exit/classify.rs`) and a `kind_detail` literal — across ~75 impls and ~500 rows in `crates/ocx_cli/src/exit/*.rs`. Consistency rests on ~2,000 lines of `syn` scaffolding in `exit.rs` (`produced_slugs`, `ALIASES`, `COMPUTED_CODE_SLUGS`, `classify_baseline_7adaea62.json`). No tier crate knows its own codes, so a satellite (ocx-mirror) reclassifies.
- **CLI contract.** `CONTRACT` report roots are strings (`command/contract.rs`); command names live in three tables (`app.rs` `canonical_command_name`, `CONTRACT`, `deprecated.rs`); `RENAMED` is `&[(&str, &str)]` split at runtime and regex-parsed by `test/lint/test_deprecated_spellings.py`; `RENAMED_ENV` copies `ocx_env::RETIRED`; schema ids repeat version consts; sweep reports carry two version literals; plain-text status words hand-copy serde names.
- **Environment and sdkgen.** `EnvLock::set/remove` take a string (~380 literal call sites — a typo is a silent no-op); `Child::Forward` is read by nothing while `apply_ocx_config` hand-lists the forwards; git passthrough tables hold env names as strings; sdkgen lint/compat rule ids are strings (`"L05"`, `"D01"`) and ledger/waiver rules are `String`; the launch firewall (`SPAWN_ALLOWED`) is a path-string token scanner.

## Decision Drivers

- A drift between two copies of one fact must fail `cargo check`, not a later test — and never be possible to express at all where a type can prevent it.
- **Zero wire change.** Every published byte stays: `website/src/public/schemas/errors/v1.json`, `reports/v2.json`, `cli.json`, the schema goldens under `crates/ocx_schema/tests/golden/`, every slug, exit code, flag spelling and env name.
  *Amended 2026-10-07 by [`adr_exit_code_taxonomy.md`](./adr_exit_code_taxonomy.md) (owner decision): exit codes 83–87 and their `error.kind` values are retired, 82 becomes `Unsupported`, and the error document moves to v2. This driver holds for everything else.*
- Crates are self-contained: a tier crate's error type carries its own classification.
- Delete the test scaffolding a type now makes redundant; keep only tests that check what no type can (filesystem paths, the live clap tree, the wire goldens).

## Considered Options

1. **Keep strings + tests** (status quo). Rejected: owner direction; every new variant edits three places.
2. **`macro_rules!` rows inside `ocx_cli`** (one row per variant generating `classify`/`kind_detail`/`DETAILS`). Keeps the crate-split ADR as is, no new crate. Rejected as the target but **kept as the recorded fallback for D2**: classification stays out of the crates, so they stay non-self-contained.
3. **Per-variant derive in the declaring crate** (chosen for D2), plain `macro_rules!`/enums/consts everywhere else.

## Decision

Each item is one Done criterion. "Typed" means the compiler rejects the drift the item names. Every item keeps the wire byte-identical (Decision Driver 2, as amended) and lands with its redundant source-scanning tests deleted.

- **D1 — `ErrorCategory` from one macro.** `crates/ocx_exit/src/error_category.rs`: the enum, `ALL` and `summary()` are generated by one `macro_rules!` table in the style of `exit_codes!`. Keep the `pinned_kind`/`pinned_value` golden pins.
- **D2 — Classification declared on the variant, in the declaring crate.** New proc-macro crate `crates/ocx_exit_derive` providing `#[derive(Classify)]`; the traits (`ClassifyExitCode`, `ClassifyErrorKind`), `DetailEntry` and the family registry move into `ocx_exit`. Per variant: `#[exit(DataError, slug = "…", summary = "…")]`; `#[exit(delegate)]` defers to the `#[source]`'s classification (today's `chain_detail` / `e.kind_detail()` arms); `#[exit(with = path::to_fn)]` is the explicit escape hatch for a computed or guarded row. A variant with no attribute does not compile. `kind_detail` returns `&'static DetailEntry`, so an unregistered slug cannot be produced and slug and code cannot diverge. Foreign errors (`std::io::Error`, `oci_client`, `docker_credential`) stay classified in `ocx_cli`. `scripts/crate_map.toml` gains the needed `ocx_exit`/`ocx_exit_derive` edges (`ocx_util`, `ocx_env`, `ocx_trust` have none today); `adr_crate_split_workspace.md` E3 is inverted (tier crates declare, `ocx_cli` only walks the chain and owns foreign types) and E4 is restated (`ocx_exit` defines the classification traits but knows no concrete error type; the derive is a build-time dependency). `no_classification_in_libraries` (`crates/ocx_test_support/tests/workspace_structure.rs`) is replaced by its inverse. **Fallback** (record the reason in the PR if taken): option 2, `macro_rules!` rows inside `ocx_cli`.

  **Implementation note (2026-10-05).** The build differs from the D2 text as follows. `kind_detail` returns `Detail<'a>`, not `&'static DetailEntry`: `Detail::Fixed(&'static DetailEntry)` or `Detail::Chain { fallback, from }`, the second so the binary can resolve a slug through a cause chain only it can classify. The grammar that shipped is `Code, slug, summary`, `defer(Code)` (answers `None`, publishes under `Code`), `delegate` / `delegate = path`, `chain`, `chain = field`, and `with = fn, rows(…)`; type level `reserve(…)` (a published row no variant answers with) and `family = "…"`. A `with` function returns `Pick` built from a `Row` it was handed, so it cannot name an undeclared slug. The binary lists its types once in `ocx_exit::families!(…)`, which generates `try_classify` and `detail_registry`; `: rows_only` lists a type for its rows alone and still demands both traits. `CommandError` (runtime-held code, no slug) keeps a hand `ClassifyExitCode` impl and is the one exception. A direct `classify()` on a `chain = field` variant answers the fallback code; the binary's resolver walks the field's chain and answers the first classified cause. Decided: documented on the trait, not changed, because only the binary can classify the foreign causes in that chain.
- **D3 — One family registry.** The per-file `try_downcast`/`downcast_arm!` ladders, `DETAIL_FAMILIES` and `exit.rs`'s `detail_registry()`/`try_classify` come from one list, so a type cannot be registered but unarmed. `every_utility_error_reaching_the_cli_is_armed` stays (it needs name resolution).
- **D4 — `UrlRejection` carries a kind.** `ocx_oci/src/endpoint.rs` gets an exhaustive `UrlRejectionKind`; the slug is not derived from the exit code by a wildcard.
- **D5 — Retire the `syn` classification scaffolding.** Every `exit.rs` test whose property D2/D3 makes a compile error is deleted; `classify_baseline_7adaea62.json` is re-pointed at the generated `DETAILS` (one byte-identical check of slug → code → summary) or retired once `errors_schema_matches_golden` and a generated-rows snapshot cover it.
- **D6 — Typed report roots.** `Printable` gains `const ROOT: &'static str`; `CONTRACT` uses `OutputMode::report::<T>()`; `RootVisitor::root::<T>()` drops its name argument. A typo or renamed root fails to compile.
- **D7 — Command leaves are an enum.** A `Leaf` enum with exhaustive `path()` and `contract()`; `Command` maps to `Leaf`; `canonical_command_name`, `CONTRACT` and `deprecated.rs` read from it. Frozen spellings (`"direnv"`, `"run"`) stay explicit. A new command without a contract entry does not compile.
- **D8 — Deprecated spellings are typed.** `Renamed { path, old: Spelling::{Command, Long, Short}, new }` consts; dispatch sites take the const; hidden arg ids are derived, never hand-typed; `RENAMED_ENV` is deleted (derived from `ocx_env::RETIRED`); the removal release is one typed const (`Release { major, minor, patch }`) shared by `retired.rs`, `deprecated.rs` and `cli.json`. `test/lint/test_deprecated_spellings.py` reads `cli.json`'s `deprecated`/`retired` fields instead of regex-parsing Rust. Warning text stays byte-identical.
- **D9 — Schema ids from version consts.** `ERRORS_ID`, `CLI_SCHEMA_ID`, `REPORTS_ID`, the project-lock and execution-record ids are built from their version consts (`LockVersion::V3`, execution-record `SCHEMA_VERSION`, a new reports version const). No version literal appears twice.
- **D10 — One sweep version.** `SweepReport<R>` uses `R::SCHEMA_VERSION`; the separate `SWEEP_SCHEMA_VERSION` consts go.
- **D11 — Status words from serde.** One macro (or one helper over serde) generates serde names, `as_str()` and `ALL` for every status enum that prints a plain-text word (`sweep.rs`, `forge_report.rs`, `package_copy.rs`, `package_cascade_check.rs`, `shell_state.rs`).
- **D12 — sdkgen rule ids are enums.** `enum Rule` (L01…L18, C01…C09) and `enum Code` (compat codes) via `macro_rules!` with `ALL`/`id()`/`title()`; `Finding.rule` holds the enum; `REPORTS_ONLY` becomes `applies(Kind)`; ledger and waiver `rule` fields deserialize into a typed enum (`Code | Doc | Semantic`), so an unknown rule fails at parse time. TOML syntax unchanged.
- **D13 — `EnvLock` takes declarations.** `ocx_env::overrides`: `set(&'static EnvVar, …)`/`remove(&'static EnvVar)` plus `set_raw`/`remove_raw` for foreign or fixture names; every declared-name literal call site is rewritten to the static. A misspelled declared name is a compile error.
- **D14 — `Child::Forward` drives forwarding.** `apply_ocx_config` (`crates/ocx_config/src/env.rs`) forwards through `forward(&'static EnvVar, …)`, and one test asserts the forwarded set equals the set declared `child = Forward`.
- **D15 — git passthrough tables are declarations.** `crates/ocx_announce/src/forge/git_command.rs` `UNIX_PASSTHROUGH`/`WINDOWS_PASSTHROUGH` become `&[&'static EnvVar]` (shared `COMMON` + `WINDOWS_EXTRA`); undeclared and secret names fail to compile. Git-written names (`SET`, `INJECTED`, `NEVER`, `NO_LAZY_FETCH`) stay strings.
- **D16 — The launch firewall uses clippy.** `clippy.toml` bans `std::process::Command`/`tokio::process::Command` (disallowed-types) and `Launch::exempt`/`CommandExt::exec` (disallowed-methods); each former `SPAWN_ALLOWED`/`EXEMPTION_ALLOWED` row becomes an `#[expect(…, reason = "…")]` at its site, so a stale allowance fails the build. The token scan stays only for files the workspace does not compile (`ocx_sdkgen/templates/**`, `tests/golden/**`).
- **D17 — Shared media-type consts.** `ACCEPTED_MANIFEST_TYPES` is one const in `ocx_oci::media_type` used by `verify/`, `attest/` and `sign/pipeline.rs`; `attest.rs`'s `*_WRITTEN` consts reference the accepted-table entries.

## Not changing (recorded so the run does not churn on them)

`ocx_env::dynamic()`/`dynamic_secret()` callers (names are data; `DYNAMIC_READS` ratchet is right) · `RETIRED.name` strings (old spellings must stay outside the registry) · `credential_keys()` pinned literals · `ADR_MAP` vs `crate_map.toml` (deliberate second copy) · filesystem-checked path allowlists (`client.rs`, `signing_instant.rs`, `activate.rs`, `ENGINE_TOKENS`, `ALLOWED_WARN_SITES`) · `host_capabilities` loader paths · sdkgen's JSON-only tables (`SUCCESS_STATUSES`, `OWNED_GLOBALS`, `OCX_METHODS`, `RESERVED_TYPES` — sdkgen links no `ocx_*` crate) · `ocx_shim` env literals (shim size budget) · `ENV_FLAGS` (gain minor) · `RECOGNISED_BODIES` and test-only `COMPOSING_COMMANDS`.

## Consequences

- One edit per new error variant, command, report root, deprecated spelling or rule id; the compiler names every missing counterpart.
- ~2,000 lines of `syn`/regex test scaffolding deleted; the wire goldens and the live-clap-tree tests remain the outer guard.
- ocx-mirror (lockstep consumer) must follow the `ocx_exit` API move (traits, `DetailEntry`) in the same change series: `task satellite:verify` green against `feat/ocx-env-port`.
- Risk: D2 is the large item (~15 crates' error enums). It can fall back to option 2 without blocking D3–D17.

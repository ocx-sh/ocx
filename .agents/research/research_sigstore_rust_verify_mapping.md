# Research: sigstore-rust capability mapping, verify side

## Metadata

**Date:** 2026-11-23
**Domain:** security
**Triggered by:** discussion `.agents/discussions/rekor-v2-sigstore-rust.md`
**Expires:** 2027-02-23 (sigstore-rust at 7fbe058a; three breaking 0.x releases in the prior 30 days)

## Direct Answer

Facts only, no recommendation. Paths into B are relative to the clone root, prefixed `sigstore-rust:`; "X" is `crates/ocx_sign`, `crates/ocx_trust` in this repo.

B has one entry point, `Verifier::verify(artifact, &Bundle, &impl Policy)` (`sigstore-rust:crates/sigstore-verify/src/verify.rs:605`), that does Fulcio chain, SCT, signing-time, identity/issuer, Rekor v1 SET, Rekor v1/v2 inclusion proof and checkpoint, RFC 3161 timestamps, DSSE/message signature and tlog-entry consistency in one call, offline, on a `TrustedRoot`. It also has a managed-key policy (`PublicKeyVerificationPolicy`).

B covers, with no X equivalent today: RFC 3161 timestamp verification, Rekor v2 (`hashedrekord/0.0.2`) checkpoint and inclusion proof, bundle v0.1/0.2/0.3 structural validation, SCT verification, per-time-window trust-root validity, an embedded production/staging/GitHub trust root.

B has no equivalent for: cosign simplesigning (`.sig` sidecar), legacy cosign `dev.sigstore.cosign/bundle` annotation, `.att` sidecar scheme, arbitrary-OID certificate claims, regex identity rules, a trust-on-first-use Rekor key, a keyless verify with no authenticated signing time, a key-mode bundle with no tlog entry and no timestamp, a promise-only (no inclusion proof) rejection, and a Rekor v2 `dsse/0.0.2` bundle (parse fails). Section numbers below match the task list.

## Findings

### 1. Bundle parse and version handling

- **X:** parses bundle JSON into the protobuf-generated `sigstore_protobuf_specs::...::Bundle` with `serde_json::from_slice`, after a size cap: `crates/ocx_sign/src/sign/bundle.rs:273-279` (7 lines; the cap constants are X's). No media-type check at parse. Shape dispatch in `BundleParts::from_bundle` (`verify/pipeline.rs:1617-1664`): `Certificate` (v0.3) and `X509CertificateChain` (v0.1/0.2) both map to `Keyless`, `PublicKey` to `Key`; `messageSignature` content is refused in both modes (`pipeline.rs:1630`). Tlog entries read by `BundleTlog::from_entry` (`pipeline.rs:1572-1599`); mandatory inclusion proof and promise (`pipeline.rs:1575-1585`). Bundle v0.3 media type const in `ocx_oci::referrer::media_types`; a v0.1 const is private at `verify/simplesigning_read.rs:44`. Candidate-listing also parses bundles: `verify/candidates.rs:236-270`.
- **B:** hand-written serde types, not protobuf types. `Bundle`, `MediaType {Bundle0_1, Bundle0_2, Bundle0_3}` (`sigstore-rust:crates/sigstore-types/src/bundle.rs:31,101`); `MediaType::from_str` accepts exactly four strings, including `...+json;version=0.3` as an alias (`bundle.rs:81-92`); anything else is `InvalidMediaType`. `Bundle::from_json` (`bundle.rs:126`). `VerificationMaterialContent::{Certificate, X509CertificateChain, PublicKey}` (`bundle.rs:281-292`), `SignatureContent::{MessageSignature, DsseEnvelope}` (`bundle.rs:177`). `Bundle`, `TransparencyLogEntry`, `TrustedRoot` and others are `#[non_exhaustive]` with pub fields: constructible only via constructors/builders (`BundleV03`, `sigstore-rust:crates/sigstore-bundle/src/builder.rs:47`) or JSON.
- Structural validation per version: `validate_bundle_with_options` (`sigstore-rust:crates/sigstore-bundle/src/validation.rs:120`): v0.1 requires a promise, v0.2/0.3 require an inclusion proof (when requested), v0.3 refuses a certificate chain.
- `KindVersion` is a closed enum `{HashedRekordV001, HashedRekordV002, DsseV001, IntotoV002}` (`bundle.rs:432-441`); deserialization of any other `kind/version` fails the whole bundle parse (`bundle.rs:487-495`). X reads `kind_version` as an optional proto field and never rejects at parse.
- Compatibility with the protobuf JSON is tested in `sigstore-rust:crates/sigstore-protobuf-compat` (test-only, never published, `src/lib.rs:1-11`). No protobuf types are public API in B.
- X non-test lines: ~7 (`parse_bundle`) + 92 (`BundleTlog`/`BundleParts`, `pipeline.rs:1550-1665`) + 36 (`candidates.rs:230-270`).
- **Verdict:** `replaceable with adapter`. Type swap: every `sigstore_protobuf_specs` field access in X (`pipeline.rs`, `dsse.rs`, `attestation_sidecar.rs`, `simplesigning_read.rs`, `candidates.rs`) changes to B's types; X's own bounds and refusals (messageSignature refused, promise+proof both mandatory) stay X's.

### 2. Keyless bundle verification

- **X:** chain, SCT, signature, tlog-body consistency come from `sigstore` 0.14: `Verifier::new(RekorConfiguration::default(), trust_root)` at `verify/pipeline.rs:916`; call at `pipeline.rs:1376-1378` with `offline = true` and a deferring policy (`PolicyDeferredToOcx`, `pipeline.rs:2225-2231`, always `Ok`). Errors folded by `map_verification_error` (`pipeline.rs:2234-2248`: `Bundle`→`BundleParseFailed`, `Certificate`→`CertChainInvalid`, `Signature`→`SignatureInvalid`). Identity/issuer/claims are X's own: `verify/identity.rs:87-139` (`matching_policies`), reading SAN (`:39-47`) and the Fulcio issuer OID `1.3.6.1.4.1.57264.1.8` (`:18,49`) from the DER with `x509-cert`; arbitrary-OID claim match `claims_match` (`:63-85`, selector OID + raw/DER encoding, string equality); regex/scope rules are `ocx_trust::IdentityRule`. X refuses a trust root with no CT key (`pipeline.rs:905-914`, `NoCtLogKey`). Signing instant from tlog `integratedTime`, checked against leaf validity by X (`verify/tlog.rs:94-111`, CVE-2024-55655 note). Builder pin: `dsse.rs:220-255`.
- **B:** `Verifier::verify` steps 0-8 (`sigstore-rust:crates/sigstore-verify/src/verify.rs:578-604`; impl `verify_certificate` `:678-841`):
  - chain: webpki against Fulcio anchors from the trust root, only anchors whose `validFor` contains the time, at every verified signing time (`verify_impl/helpers.rs:300`); CODE_SIGNING EKU; the verified path yields the issuer for SCT.
  - SCT: `verify_sct` (`verify_impl/sct.rs:187`) against CT log keys; **optional**: `VerificationPolicy::skip_sct()` (`verify.rs:320`), documented for trust domains whose certs carry no public CT SCTs. With `skip_sct`, a trust root with no `ctlogs` constructs (`Verifier::new` allows empty lists, `verify.rs:455-460`). Private CA without SCT: possible through `skip_sct`. Chain skip also exists: `skip_certificate_chain()` (`verify.rs:309`, "unsafe").
  - signing-time window: authenticated times only, from RFC 3161 timestamps and, for Rekor v1, an integrated time with a verified SET (`helpers.rs:200-232`); each time must be inside the leaf validity (`validate_certificate_time`, `helpers.rs:235`); the integrated time is also checked not-in-future and inside the leaf validity (`verify_impl/tlog.rs:29-54,65-78`). No caller-supplied time; no "unlogged" fallback: with no verified time source it errors `NoVerifiedTimestamp` (`helpers.rs:217-231`).
  - identity: `VerificationPolicy { identity: Option<IdentityMatcher>, issuer: Option<String> }` (`verify.rs:235-240`); `IdentityMatcher::{Exact, Email, Uri}` (`:156`), string equality only, no regex, no set (one matcher, one issuer); `VerificationPolicy::new` requires both, `any_identity()` requires neither (`:247,257`).
  - claims: `CertificateInfo.ci_claims: FulcioCiClaims` (`sigstore-rust:crates/sigstore-crypto/src/x509.rs:68,93`) exposes fixed named fields for `.1.9`-`.1.15` and more, plus `DeprecatedGitHubClaims`; returned in `VerificationResult::certificate()` (`verify.rs:410`). No API to match an arbitrary OID, no raw extension access. Not used by `VerificationPolicy`: matching is the caller's, after verify.
  - OIDC issuer is read by `parse_certificate_info` (`x509.rs:215`); the exact extension handling (v1 `.1.1` fallback, duplicate extensions) was not read.
- X own non-test lines: `identity.rs` 123 code; `pipeline.rs:1372-1420` keyless arm (34 code).
- **Verdict:** chain/SCT/signature/time: `replaceable with adapter` (feed a B `Bundle`, `TrustedRoot`, call `Verifier::verify` with `VerificationPolicy::any_identity()`, then X runs its own identity/claims/builder checks on `result.certificate()` or its own parse). X's identity rules (regex, ANY-of, arbitrary OIDs): `X-specific, not a library concern`. Keyless verify with no authenticated time (X's `--allow-unlogged-signature` sidecar path anchors on `notBefore`, `simplesigning_read.rs:296-325`, `attestation_sidecar.rs:343-370`): `gap in B`.

### 3. Rekor v1: SET, inclusion proof, checkpoint

- **X:** `verify/tlog.rs`: `verify_set` canonicalizes `{body, integratedTime, logIndex, logID}` with `serde_json_canonicalizer` and checks the signature with `sigstore::crypto::CosignVerificationKey` (`:53-66`, P-256 ASN.1 only, `rekor_key` `:47`); `verify_inclusion` builds a `sigstore::rekor::models::InclusionProof` and calls its `verify(body, key)` (`:68-91`), which also covers the checkpoint signature. `BundleTlog::from_entry` makes the SET and the proof mandatory together (`pipeline.rs:1575-1585`). X keeps one Rekor key per `logId`, resolved by `RekorKeyMemo` (`pipeline.rs:1700-1818`): memo, pinned trust material, then an online fetch of `/api/v1/log/publicKey` (trust on first use, `:1777-1818`); offline with no pinned key is refused.
- **B:** `verify_entry_inclusion` (`sigstore-rust:crates/sigstore-verify/src/verify_impl/tlog.rs:118`): Merkle inclusion (`:143`, via `sigstore-merkle::verify_inclusion_proof`, `sigstore-rust:crates/sigstore-merkle/src/proof.rs:22`), checkpoint signature (`verify_checkpoint` `:169`, signed-note parse `Checkpoint::from_text`, `sigstore-rust:crates/sigstore-types/src/checkpoint.rs:85`, tries every key matching the 4-byte hint, v1 additionally cross-checks the proof root against the checkpoint root), SET (`verify_set` `:233`, same canonical payload as X, key must be valid at the integrated time). Rekor keys come only from `TrustedRoot::rekor_keys()` (`sigstore-rust:crates/sigstore-trust-root/src/trusted_root.rs:244`) keyed by sha256 log id.
  - Differences from X's rule: B accepts a v0.1 bundle with a SET and no inclusion proof and then reports `tlog_verified = true` (`validation.rs:75-87` requires only the promise for v0.1; `tlog.rs:118-133` skips proof checks when absent). X refuses it (`RekorInclusionProofAbsent`).
  - The primitives `verify_set`, `verify_checkpoint`, `verify_entry_inclusion` are `pub fn` inside the private module `verify_impl` (`sigstore-verify/src/lib.rs:29`, `mod verify_impl;`): not callable by X. Only `Verifier::verify` reaches them. Public pieces: `sigstore-merkle::verify_inclusion_proof`, `sigstore_types::Checkpoint`, `sigstore_crypto::VerificationKey::verify`, `Keyring`.
  - No TOFU: a key must be in the `TrustedRoot`; `TrustedRoot` is `non_exhaustive`, so a root holding a fetched key has to be produced as JSON. `Verifier::new` rejects duplicate log ids and unparseable keys (`verify.rs:464-490`).
- X own non-test lines: `tlog.rs:1-93` 64 code (call sigstore); `pipeline.rs:1667-1698` 25 code (`verify_rekor_set`, `verify_rekor_entry`); key memo + fetch `pipeline.rs:1700-1818` 79 code.
- **Verdict:** SET + inclusion + checkpoint: `B covers more than X (X code could shrink)` on the bundle path (`tlog.rs` 64 and `verify_rekor_entry` 25 become unnecessary once the bundle goes through `Verifier::verify`). The legacy-annotation path (section 7) has no public SET entry point. The TOFU key fetch and memo: `X-specific, not a library concern`. The "proof mandatory with SET" rule: `X-specific` (B is more permissive for v0.1).

### 4. Rekor v2

- **X:** none. `sign/rekor.rs:4-6` states v2 unsupported (ocx-sh/ocx#107); a v2 bundle is ranked unparseable (`pipeline.rs:2637` per prior recon).
- **B:** one `verify` call handles v1 and v2 entries in the same code path (branch on `KindVersion::HashedRekordV002`, `verify_impl/tlog.rs:36,148-155`, `helpers.rs:117`).
  - Checkpoint: signed note, the v2 proof root is taken from the signed checkpoint and `log_index`/`tree_size` from the entry/checkpoint, the duplicated proof fields are ignored (`tlog.rs:143-166,169-198`); `validate_inclusion_proof_structure` range-checks the leaf index (`validation.rs:210-250`).
  - Inclusion proof: the proof hashes carried in the bundle, verified with `sigstore-merkle` (`proof.rs:22`). No tile fetch in verification; tiles are fetched only by the write-side `RekorV2Client` (`sigstore-rust:crates/sigstore-rekor/src/client.rs:194-268`: `create_entry`, `get_checkpoint`, `get_tile`, `get_entry_bundle`).
  - Timestamp: v2 entries carry no integrated time; the certificate path then requires a verifiable RFC 3161 timestamp or errors `NoVerifiedTimestamp` (`helpers.rs:217-224`). RFC 3161: `extract_tsa_timestamps` (`helpers.rs:44`), `sigstore-tsa` (`sigstore-rust:crates/sigstore-tsa/src/verify.rs`, `verify_timestamp_for_authority` `:260`), validated against the TSA chains and `validFor` windows in the trusted root; every timestamp present must verify, for keyless and managed-key.
  - Entry kinds: v2 `hashedrekord/0.0.2` only (bundle with message signature or DSSE content, `verify_impl/rekor.rs:30-35`). `KindVersion` has no `dsse/0.0.2` (`bundle.rs:432-441`) although `sigstore-rekor` has a `DsseV002Body` type (`sigstore-rust:crates/sigstore-rekor/src/body.rs:28-30,272-292`) not referenced from any verify code (searched the repo: only `body.rs`). A bundle whose tlog entry is `dsse/0.0.2` fails to parse at `bundle.rs:487-495`.
  - Key hint check: key validity at integrated time applies to v1 only; a v2 entry's log key is matched by checkpoint hint among keys with `usable_for_verification` (`sigstore-trust-root/src/trusted_root.rs` ~`:200-300`, not read in full).
- **Verdict:** `B covers more than X` for `hashedrekord/0.0.2`, RFC 3161, checkpoint. `gap in B` for v2 DSSE (`dsse/0.0.2`) entries as a bundle member; X's attestations and cosign-v3 DSSE image signatures are DSSE, so a v2 log entry for those is the unsupported shape.

### 5. Key-mode verification with a caller key

- **X:** verify path `verify/pipeline.rs:1424-1503` (the keyless `sigstore::bundle::verify` reads its key only from a certificate, `:1422`): PAE built by X (`crate::attest::dsse::pae`, `:1434`), checked with `identity::matching_key_policies` (`identity.rs:142-178`): ANY-of over `PolicyBackend::Key(CosignVerificationKey)`, each `key.verify_signature(Signature::Raw(sig), message)` (`identity.rs:158-160`). Tlog is optional in key mode and verified only if present (`pipeline.rs:1444-1491`); an absent tlog entry stays legal (`pipeline.rs:1657`). Key loading: `ocx_trust::lib.rs:834-846` `CosignVerificationKey::try_from_pem`; remote `key_pem` entries `ocx_trust/src/publishers.rs:185-205` (maps `PublicKeyUnsupportedAlgorithmError` to an `unrecognised` refusal, anything else to `invalid`). File/env key reading, 64 KiB bound, `lib.rs:775-832`: X's own.
- **B:** `PublicKeyVerificationPolicy::new(DerPublicKey)` (`sigstore-rust:crates/sigstore-verify/src/verify.rs:47-80`) and `Verifier::verify_public_key` (`:843-929`): requires the bundle material to be `publicKey` (`prepare_public_key` `:1054-1071`), verifies inclusion proof/checkpoint/SET unless `skip_tlog_unsafe()`, verifies any RFC 3161 timestamps present, then the DSSE-PAE or message signature with the supplied key, then tlog-entry consistency binding the key (`verify_tlog_consistency_with_key`, `verify_impl/rekor.rs:24`). One key per policy: ANY-of over several keys needs one call per key (or a loop). Supported schemes (`sigstore-rust:crates/sigstore-crypto/src/signing.rs:17-50`): ECDSA P-256/P-384/P-521, Ed25519, RSA PKCS#1 v1.5 and PSS (SHA-256/384/512), ML-DSA. Key algorithm and scheme detected from the SPKI: `VerificationKey::from_spki` (`sigstore-crypto/src/verification.rs:221`, default scheme per algorithm: RSA → `RsaPkcs1Sha256`, P-256 → SHA-256, P-384 → SHA-384, `signing.rs:148-158`); ECDSA verification is ASN.1 DER (`aws_lc.rs:78-82`). PEM: `DerPublicKey::from_pem` accepts only the `PUBLIC KEY` label (`sigstore-rust:crates/sigstore-types/src/encoding.rs:300-312`); no `RSA PUBLIC KEY` (PKCS#1) PEM.
  - `skip_tlog_unsafe` does not make a bundle with no tlog entries and no RFC 3161 timestamp verifiable: `validate_common` returns `MissingSigningTimeEvidence` (`validation.rs:154-160`). X accepts exactly that shape (offline `cosign sign --key`).
  - B's `VerificationKey` has no `Clone`/`Debug` (`verification.rs:189`); `DerPublicKey` has both (`encoding.rs:133`).
- X own non-test lines: key arm `pipeline.rs:1422-1503` 66 code; `identity.rs:142-178` 32 code; `ocx_trust` key sites 39 code (counted in the summary).
- **Verdict:** key algorithms and PEM/DER loading: `replaceable with adapter`; the PKCS#1 PEM form was not checked in X's current loader (`sigstore` 0.14 `try_from_pem`; not read). Key-mode bundle with neither tlog entry nor timestamp: `gap in B`. ANY-of across policy keys, hint handling, builder pin: `X-specific, not a library concern`.

### 7. Cosign legacy: simplesigning, `.sig` / `.att` sidecars, Rekor "bundle" annotation

### 8. Trust root: load, TUF, private instance, injection, cache

- **X:** `verify/trust_root.rs` (143 code): `TrustRoot` is a flattened value `{ der_certs, ctfe_keys, rekor_keys }` (`:56-66`), no validity windows, no TSA. `load_embedded` (`:73-85`) = SSRF guard (`resolve_sigstore_url`) then `SigstoreTrustRoot::new_with_client(Some(cache_dir), client)` with `sigstore_http_client()` (shared reqwest client with pinned DNS resolver, extra CA roots, proxy), 60 s deadline (`:34-47`). `load_trusted_root_json` (`:136-153`) uses `from_trusted_root_json_unchecked`. Rekor key can be pinned from PEM (`:155-164`). The sigstore `TrustRoot` trait is implemented by hand (`:203-220`). `trust_cache.rs` (88 code): own JSON snapshot `{fulcio_der_certs, ctfe_keys, rekor_public_key_pem, cached_at, ttl}` under `state/trust_root/<rekor-authority>.json`. `trust_resolve.rs` (83 code): six-rung ladder, offline pinned-Rekor-key gate (`:104-111`).
- **B:** `TrustedRoot` JSON model with windows (`sigstore-rust:crates/sigstore-trust-root/src/trusted_root.rs:13-33`, `from_json` `:208`, `from_file` `:213`, embedded constants `:359-369`, `from_embedded(SigstoreInstance)` `:434`). TUF: `TufConfig` (`sigstore-trust-root/src/tuf.rs:123-136`): `for_instance`/`production`/`staging`/`github`, `custom(url, TufBootstrap)` (`:167`; bootstrap root bytes, or `UnsafeCachedRoot`), `custom_from_file` (`:199`), `with_cache_dir` (`:208`), `without_cache` (`:224`), `offline()` (`:246`: re-runs full TUF verification over the cache, no network, errors on missing/invalid cache), **`with_http_client(reqwest::Client)`** (`:218`). Entry points `TrustedRoot::from_tuf(config)` (`:486`), `from_tuf_at(config, time)`, `from_tuf_target(...)`, `fetch_trust_material`. B's reqwest is 0.13 (`sigstore-rust:Cargo.toml:63`), same minor as X's lock (0.13.5) and the re-export `sigstore_trust_root::reqwest` is provided. Lower level: `sigstore-tuf::Repository` trait (`sigstore-rust:crates/sigstore-tuf/src/transport.rs:30-37`, pluggable transport) and `Updater::new(repo, root_bytes)` (`client.rs:48`), but `TrustedRoot::from_tuf` builds its own `HttpRepository` from `TufConfig` (`tuf.rs:339-343`), so a non-reqwest transport means driving `Updater` directly.
  - Cache: TUF metadata/target cache on disk (`FileStore`, `sigstore-tuf/src/cache.rs:58`; default dir via `directories::ProjectDirs`, overridable). ### 11. Public-type leakage: replacement for `sigstore::crypto::CosignVerificationKey`

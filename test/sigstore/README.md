# Local Sigstore stack (test only)

Everything in this directory exists to run a **real** Sigstore stack —
Fulcio, Rekor, a CT log, and an OIDC issuer — against the acceptance suite,
replacing the Python fake that previously stood in for it.

## The keys in `keys/` are deliberately committed and are not secrets

They are generated by [`generate-test-keys.sh`](generate-test-keys.sh), they
sign nothing outside this repository's test stack, and every one of them is
worthless to an attacker: the CA they root is trusted only by a
`trusted_root.json` that a test explicitly passes to `--sigstore-trusted-root`.

They are committed rather than generated per run so that
[`trusted_root.json`](trusted_root.json) can be committed too. That file is the
stack's trust anchor, and a trust anchor that changes on every CI run is one
nobody can review. Regenerate both together:

```sh
cd test
./sigstore/generate-test-keys.sh
uv run ./sigstore/generate-trusted-root.py

# then, with the stack up, check the file against the running services:
docker compose --profile sigstore up -d
uv run ./sigstore/wait-for-stack.py
uv run ./sigstore/verify-trusted-root.py
```

**No production verification path can reach this material.** It is trusted only
when a caller names it — `--sigstore-trusted-root test/sigstore/trusted_root.json` — and
ocx's default trust root is the public-good Sigstore root embedded in the
`sigstore` crate.

## Files

| File | Purpose |
|---|---|
| `generate-test-keys.sh` | Mints the Fulcio CA, the CT log signer, and the Rekor signer |
| `generate-trusted-root.py` | Builds `trusted_root.json` from those keys, without needing `cosign` or a Go toolchain |
| `wait-for-stack.py` | Polls the four HTTP services from the host — four of the seven images are distroless, so a compose `healthcheck:` cannot run inside them |
| `verify-trusted-root.py` | Checks `trusted_root.json` against what the running Fulcio and Rekor actually serve |
| `trusted_root.json` | The stack's trust anchor, in the same protobuf-JSON shape `cosign trusted-root create` emits |
| `dex-config.yaml` | The OIDC issuer, with one static password user so tests can mint a token non-interactively |
| `fulcio-config.json` | Tells Fulcio to accept tokens from that issuer |
| `get-token.py` | Mints an OIDC token via the resource-owner password grant |

## Self-hosting

`generate-trusted-root.py` is also the worked example for the self-hosting
documentation: an operator running their own Fulcio, Rekor and CT log produces
exactly this file for their own key material, and points `--sigstore-trusted-root` at it.

The Python helpers are run with `uv run` from `test/`: they import
`cryptography`, which lives in the suite's dependency group, not on the
system interpreter.

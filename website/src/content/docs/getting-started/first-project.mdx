By the end of this page a project pins [Node.js][nodejs], teammates and CI run the identical build, and it still builds with no network. It assumes OCX is [installed][installation]. The same file format pins the tools of a repository and, as `$OCX_HOME/ocx.toml`, your [global toolchain][global-toolchain]. This page walks through the repository.

## Pin and run the tools \{#project-toolchain\}

Every clone of this repository should build with the same Node.js, with nothing installed machine-wide.

<ShellSession title="Pin Node.js and run it">

\<\<\< @/_scripts/first-project/init.sh\{sh\}

```text
created /home/you/my-project/ocx.toml
```

\<\<\< @/_scripts/first-project/add.sh\{sh\}

```text
Binding  Group    Digest
node     default  sha256:...
```

\<\<\< @/_scripts/first-project/exec.sh\{sh\}

```text
v24.22.3
```

</ShellSession>

`ocx add` resolved the tag to a digest, wrote `ocx.lock` and added one line to `ocx.toml`:

```toml title="ocx.toml"
#:schema https://ocx.sh/schemas/project/v1.json

[tools]
node = "ocx.sh/nodejs/node:24"
```

Go deeper: [project toolchain guide][project-guide] and the [project file reference][project-file].

## Share the pin \{#share\}

A teammate who clones the repository gets your build with one command. Commit both files first. `git init` starts a repository in this new directory; skip it in an existing one.

<ShellSession title="Commit the pin">

```sh
git init
git add ocx.toml ocx.lock
git commit -m "Pin Node.js with ocx"
```

</ShellSession>

On a fresh clone, one command downloads the locked packages:

<ShellSession title="On a fresh clone">

\<\<\< @/_scripts/first-project/pull.sh\{sh\}

</ShellSession>

They run the same bytes you did. Go deeper: [lock and reproduce][lock-guide] and [run project tools][run-guide].

## Use them from your shell \{#shell\}

Inside the repository, `node` is the pinned one. Outside, your shell finds whatever `node` it found before.

<ShellSession title="Enter the repository">

```sh
cd .. && cd my-project
node --version
```

```text
v24.22.3
```

</ShellSession>

This needs the shell hook, which [`ocx self setup`][what-setup] wires into your profile, and your [consent][consent], which `ocx init` and `ocx add` recorded for this project. The hook puts the locked tools on `PATH` and sets the variables their packages declare at the next prompt, and takes both away when you leave. Go deeper: [shell integration][shell-integration] and [shell troubleshooting][shell-trouble].

## Run the same tools in CI \{#ci\}

A CI job must refuse a stale lock and build with exactly the locked tools.

<ShellSession title="CI commands">

</ShellSession>

`ocx lock --check` fails when `ocx.toml` and `ocx.lock` disagree. `--frozen` resolves tags from the local index only and never fetches an unknown tag. Go deeper: [GitHub Actions][github-actions], [GitLab CI][gitlab-ci] and [unattended CI][unattended-ci].

## Build without the network \{#offline\}

An air-gapped runner, or a laptop on a plane, still builds from what is on disk.

<ShellSession title="Offline">

\<\<\< @/_scripts/first-project/offline.sh\{sh\}

```text
v24.22.3
```

</ShellSession>

`--offline` forbids every network call, so the command works only for packages already downloaded. Go deeper: [work offline][work-offline] and [corporate mirrors][corporate-mirror].

## Keep tools current \{#update\}

Move to another Node.js version on purpose, never by accident. `ocx update` re-resolves the tags in `ocx.toml` into `ocx.lock`. `ocx upgrade` moves the tag in `ocx.toml` itself. Go deeper: [update tools][update-guide], [`ocx update`][cmd-update] and [`ocx upgrade`][cmd-upgrade].

## Everyday commands \{#everyday\}

| Command | What it does |
|---|---|
| [`ocx status`][cmd-status] | Show whether the lock matches the project file |
| [`ocx add`][cmd-add] / [`ocx remove`][cmd-remove] | Add or drop a tool in `ocx.toml` |
| [`ocx lock`][cmd-lock] | Resolve new or changed tools and rewrite `ocx.lock` |
| [`ocx update`][cmd-update] | Re-resolve tags to their current digests |
| [`ocx exec`][cmd-exec] | Run a command with the locked tools |
| [`ocx --global add`][global-add] | Put a tool on `PATH` in every shell |
| [`ocx clean`][cmd-clean] | Remove packages no project or install references |

By the end of this page you have run [Node.js][nodejs] without installing it, installed two versions side by side, switched between them and removed them, apart from the one you linked. It assumes OCX is [installed][installation]. Use this page for machine-wide installs with stable paths for editors and scripts. To get a tool on your `PATH` in every shell, use the [global toolchain][global-toolchain] instead. Package names such as `nodejs/node` resolve against the default registry, `ocx.sh`.

## Run a package once \{#quick-start\}

Run Node.js straight from the registry. The first call downloads the package. Later calls with the same version reuse the download.

<ShellSession title="Run once">

\<\<\< @/_scripts/first-package/exec.sh\{sh\}

```text
v22.23.5
```

</ShellSession>

The command ran with the package's variables layered over your own environment. Add `--clean` to start from an empty one. Nothing persists on your machine: no install, no symlink. The patch number you see depends on the current 22 release.

## Install it \{#installing\}

Make the download permanent and give it a stable path. The paths on this page assume the default home directory, `~/.ocx`:

<ShellSession title="Install a version">

\<\<\< @/_scripts/first-package/install.sh\{sh\}

```text
Package         Version                Path
nodejs/node:22  ocx.sh/nodejs/node:22  ~/.ocx/symlinks/ocx.sh/nodejs/node/candidates/22
```

</ShellSession>

The `Path` column is a candidate symlink. It points at the build installed for 22, so an editor or script can use it as a fixed path.

## Link it where you want it \{#link\}

Besides the candidate and `current` symlinks that OCX manages, you can ask for a link at a path you choose. It gives a build or an editor a stable path of your own, and the package behind it is kept from `ocx clean`. The path must not exist yet, and the flag takes one package.

<ShellSession title="Install and link">

\<\<\< @/_scripts/user-guide/install-link.sh\{sh\}

</ShellSession>

[Use stable paths][stable-paths] explains when to use it. The [`ocx package install` reference][cmd-install] lists the flag.

## Switch versions \{#switching-versions\}

Install a second version and mark it as the one you use. The `--select` flag creates a `current` symlink next to the candidates:

<ShellSession title="Install and select">

\<\<\< @/_scripts/first-package/install-select.sh\{sh\}

```text
Package         Version                Path
nodejs/node:24  ocx.sh/nodejs/node:24  ~/.ocx/symlinks/ocx.sh/nodejs/node/current
```

</ShellSession>

Run the binary through `current`. The path has no version in it:

<ShellSession title="Run through current">

```sh
~/.ocx/symlinks/ocx.sh/nodejs/node/current/content/bin/node --version
```

```text
v24.22.3
```

</ShellSession>

Point `current` back at 22, then run the same path again:

<ShellSession title="Switch back">

\<\<\< @/_scripts/first-package/select-back.sh\{sh\}

</ShellSession>

<ShellSession title="Run after switching">

```sh
~/.ocx/symlinks/ocx.sh/nodejs/node/current/content/bin/node --version
```

```text
v22.23.5
```

</ShellSession>

The path stayed the same and the version behind it changed. Installing with `--select` does not put this `node` on your `PATH`. The [next steps](#next-steps) show how to get that.

## See the environment \{#environment\}

A package can declare environment variables, such as the `PATH` entry for its `bin` directory. List what the installed package declares:

<ShellSession title="List the environment">

\<\<\< @/_scripts/first-package/env.sh\{sh\}

</ShellSession>

The output is a table with the columns `Key`, `Type` and `Value`. Each value is resolved against the install location. `ocx package exec` injects exactly these variables into the child process.

## Remove the packages \{#uninstalling\}

Remove the selected version, clear the `current` pointer and delete the package data in one command:

<ShellSession title="Remove one version">

\<\<\< @/_scripts/first-package/uninstall.sh\{sh\}

```text
Package         Status
nodejs/node:22  removed
nodejs/node:22  purged
```

</ShellSession>

A plain uninstall removes the candidate symlink and keeps the package data. Uninstall 24 that way, then let `ocx clean` delete every package nothing references anymore:

<ShellSession title="Clean up">

\<\<\< @/_scripts/first-package/clean.sh\{sh\}

</ShellSession>

The last command prints one line for each object it deletes. The 22 install is gone. The linked 24 package stays until you delete the link at `./.tools/node`, because `ocx clean` keeps what a link points at.
